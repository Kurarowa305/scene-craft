# WSL のアプリ管理と Windows の制作環境を分ける

2026-10-12、[アプリ全体と Windows・WSL の責務を決める](https://github.com/Kurarowa305/scene-craft/issues/3) の検討で、Windows にブラウザ・Blender・Photoshop と制作ファイル、WSL に会話・制作履歴・依頼の実行管理と Codex app-server を置くことを利用者と合意した。WSL 上で実接続を確認した Codex を活かし、Windows の制作アプリが扱うファイルを Windows 側に置くためである。

管理データは WSL 側の SQLite とする。すべてを一方の OS の保存領域へ集約する構成に比べ、OS 間のパス変換と、記録 DB・制作ファイルをまたぐ保存やバックアップの整合性を設計する負担が増える。制作ファイルの保存完了と記録の確定を別々に確認できる必要があり、その具体化は保存設計へ引き継ぐ。

Codex の設定・会話・認証ファイルは scene-craft 用に分け、初回は同じ ChatGPT アカウントでログインする。普段の開発用の設定や保存領域との混在を減らすため、既存ログインのそのままの共有より専用領域の管理を選ぶ。認証の保存・更新は Codex に任せ、制作バックアップから資格情報を除外する。具体的な保管設定と実機での起動は未検証である。

起動は Windows のショートカットから人間が行う。ブラウザを閉じても実行を継続し、明示的なアプリ終了では安全に停止できるところまで待つ。PC や実行プロセス終了後の制作再開は人間が指示する。この判断は生存管理の実装や Blender の操作・停止経路が成立したことを意味しない。現在の合意と未決事項は [全体設計](../design/application-architecture.md) にまとめる。
