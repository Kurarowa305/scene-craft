# 専用の会話アプリを作り、LLM 利用を ChatGPT Pro の契約内に収める

2026-10-05 の要件インタビューで、既存の会話型エージェントを入口にする提案を採らず、scene-craft 専用の会話アプリを初期から作ると決定した。利用者の費用制約により、LLM 呼び出しは ChatGPT Pro の契約内で行い、API 従量課金は許容しない。API キーによる課金経路への切り替えや、契約枠を超える追加課金を前提とした設計は採らない。

初期は手元の PC で起動し、ブラウザから使うローカル Web アプリとする。一作品に複数の会話を持ち、制作意図・採用済みの結果・制作履歴は作品単位で共有する。

初期画面には作品一覧、作品ごとの会話、生成物・編集案の確認と採否、制作履歴と手作業の登録、作風・制作方針の参照と版の選択を含める。画面の配置や見た目は UI 設計で決める。

ブラウザを閉じてもローカルの実行プロセスが動いている間は処理を継続し、画面を開き直して進捗・結果を確認できるようにする。PC や実行プロセスが終了した場合は中断として記録し、人間が再開を指示する。画面からの停止要求にも初期から対応し、人間による停止は自動再実行の対象にしない。

契約枠の利用上限に達した場合は依頼と途中状態を保存して停止し、人間が再開する。通常の自動再実行を繰り返したり、追加課金の経路へ切り替えたりしない。履歴の閲覧と手作業の記録は LLM を使わずに続けられるようにする。

バックアップ・移行の書き出しと復元も、LLM を呼ばない通常のプログラムとして初期から提供し、契約枠を使えない場合も利用できるようにする。

## 参考にする検証実装

利用者が指定した projects 配下の background-agent は、ChatGPT ログインの OAuth トークンを使って公開 Responses API へ直接接続する検証実装である。接続処理は `src/auth.mjs` と `src/engine.mjs` にあり、Codex app-server を経由しない。認証、ストリーミング、ローカルの会話履歴、画像入力、ツール呼び出しの往復処理を参照できる。Blender 連携はこの実装には含まれていない。

[公式の Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) も ChatGPT 契約枠を使う OAuth と公開 Responses API の組み合わせを案内している。API という通信手段の利用と、API 従量課金の利用を区別する。

background-agent のコードでは API キーによるフォールバックを持たず、Pro 契約と追加クレジット無効の確認は利用者の申告による。追加課金なしを自動保証できる実装とは扱わない。[公式の UI/UX guidelines](https://developers.openai.com/siwc/ui-ux-guidelines) は契約枠とクレジット残高の双方に言及しているため、OAuth を使うことだけで費用条件の充足を断定しない。

当初の確認はソース・文書の読み取りのみであり、実アカウントへの推論要求やテストは実行していない。background-agent の `docs/connection-validation.md` には、途中本文の受信は利用者確認済みで、修正後の完了応答、履歴再開、画像理解、実モデルのツール呼び出しは未検証と記録されていた。現在の検証状況は、以下の2026-10-06の補足を参照する。

## 2026-10-06 の費用運用と検証状況の補足

以下は当時の判断。費用確認の保持・無効化と確認できない場合の送信保留は、2026-10-12 の追記で変更した。

[LLM 接続と費用制約を満たす方式を決める](https://github.com/Kurarowa305/scene-craft/issues/2) の検討で、次を利用者と確認した。

- ChatGPT 側で scene-craft のクレジット利用を無効にし、人間が設定を確認する運用を採用する。初回・再接続・設定変更時の確認を運用条件とし、確認できない場合は LLM へ送信しない。確認を保持・無効化する詳細な条件は同 Issue で設計する。これは人間による確認であり、アプリが設定を自動検証しているという意味ではない。
- background-agent では、応答完了・画像入力・アプリ再起動後の会話再開・実モデルからのツール呼び出しが検証済みであることを利用者が確認した。古い検証文書の未検証表記より、この追加情報を現在の判断根拠とする。エージェントが今回再実行した結果ではなく、利用者による実接続の確認として記録する。
- 同じ接続方式を採る場合、上記の接続検証は繰り返さない。Codex app-server など異なる方式を採る場合は、変更した方式で実接続を確認する。Blender 操作や scene-craft 固有の制作履歴・停止・復旧まで検証済みとは扱わない。
- Responses API への直接接続と Codex app-server を比較し、エージェントの実行処理と文脈管理の自作を減らすことを優先して app-server を採用する方針を選んだ。理由は [ADR 0004](0004-codex-app-server-runtime.md)、認証方式など残る問いは [LLM 接続設計](../design/llm-connection.md) に記録する。

同日の追加調査で、利用者は認証も Codex に任せる案を希望した。この場合、上記の「scene-craft のクレジット利用を無効にする」外部アプリ向け設定がそのまま適用できるとは確認できていない。ChatGPT 認証でも既存クレジットを消費し得て、自動補充が有効なら追加購入につながる。その後、利用者が自動補充無効・既存クレジットなしを確認し、認証を Codex 管理に確定した。追加課金を許容しない要件を維持し、この状態を運用前提とする。先の専用 SIWC 案のアプリ単位設定に代わり、このアカウント側の確認を用いる。確認を保持・無効化する詳細は引き続き設計する。根拠と残る条件は [認証と費用の調査](../research/codex-managed-auth-billing.md) を参照する。

採用した Codex 管理の認証による app-server の [実接続確認](../research/codex-app-server-connection-validation.md) も同日に行い、応答完了・画像・会話再開・動的ツール往復などを確認した。これは background-agent の再検証ではなく、変更した接続経路の検証である。

## 2026-10-12 の費用確認の責務変更

利用者の指定により、自動補充無効・既存クレジットなしの確認と管理は利用者が担い、scene-craft 側の費用確認を不要とする。確認の画面・記録・保持・無効化を設けず、利用枠・残高が取得できなくても送信を保留しない。先の送信前確認案を採らず、利用者の運用に委ねることで基盤側の確認処理を省く。基盤が追加課金なしを自動保証するものではない。

ChatGPT Pro の契約内で利用すること、API 従量課金へ切り替えないこと、契約枠上限に達した場合に途中状態を保存して停止し人間が再開することは維持する。

## 未確定の境界

- ローカル Web アプリの具体的な起動手順と UI の配置・見た目。
- 認証切れなどの停止・復旧契約は [接続設計](../design/llm-connection.md) で合意済み。制作操作の状態照合・重複防止の具体化は実行状態とツール契約の設計へ引き継ぐ。
- background-agent の OAuth・直接接続・実行ループは持ち込まず、接続の検証観点を再利用する。scene-craft 用ツールと制作履歴の具体化は後続設計へ引き継ぐ。

接続経路の機能には [公式の Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) がある。契約枠での接続が確認できても、制作に必要な各機能の動作まで確認済みとは扱わない。
