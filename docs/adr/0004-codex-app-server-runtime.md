# Codex app-server をエージェント実行基盤に採用する

2026-10-06、[LLM 接続と費用制約を満たす方式を決める](https://github.com/Kurarowa305/scene-craft/issues/2) の比較を受け、利用者はエージェントの実行処理と文脈管理の自作を減らすことを優先し、Codex app-server を採用する方針を選んだ。scene-craft は専用の会話アプリを持ち、Codex のエージェント実行・会話再開・文脈管理を利用する。

background-agent と同じ Responses API 直接接続なら、検証済みの接続と実装を活かして制作操作を細かく制御できる。一方、モデルとツールの往復や長い会話の文脈管理を自作・保守する負担が残る。今回はその負担を減らすことを優先し、Codex の版・設定・通信仕様への追従と、scene-craft の制作履歴との連携を引き受ける。比較根拠は [接続方式の比較](../research/llm-connection-options.md) に残す。

作品、保存状態、編集案、採否、保護指定、手修正は引き続き scene-craft の責務である。Codex の会話履歴や一般的な操作承認だけでこれらの要件を満たしたとは扱わない。費用条件は [ADR 0003](0003-dedicated-chat-with-chatgpt-plan.md) を維持する。

同日、利用者は認証も Codex 管理の ChatGPT ログインに確定した。ログイン・保存・トークン更新を Codex に任せ、専用 OAuth を自作する範囲も減らす。利用者が自動補充無効・既存クレジットなしを確認し、この状態を費用面の運用前提として採用する。API 従量課金への切替は用意しない。人間の確認を前提とした採用であり、アプリが将来の費用設定まで自動保証する判断ではない。[費用調査](../research/codex-managed-auth-billing.md) に確認範囲と限界を残す。

この判断で実行基盤と認証管理の方針は確定した。同日の [実接続確認](../research/codex-app-server-connection-validation.md) では、応答・画像・動的ツール・再起動後の会話再開・圧縮・認証更新要求・中断と再開が成立した。停止・復旧の接続契約は2026-10-12に合意した。正式なツール接続方式と制作操作の整合性の詳細は後続設計へ引き継ぐ。現在の合意と残る問いは [LLM 接続設計](../design/llm-connection.md) にまとめる。

2026-10-12、費用条件の確認・管理は利用者が担い、基盤側では確認を設けず、利用枠・残高の取得失敗でも送信を保留しないと合意した。[ADR 0003 の追記](0003-dedicated-chat-with-chatgpt-plan.md) に責務の変更を記録する。
