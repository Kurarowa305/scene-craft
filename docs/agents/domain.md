# ドメイン文書

## 配置

このリポジトリは単一コンテキスト構成とする。
以下のパスはすべてリポジトリルートを基準とする。

- GLOSSARY.md：ドメイン用語集
- docs/requirements/：合意済み要件
- docs/design/：現在採用している設計。項目がまとまるごとに作成・更新する
- docs/adr/：設計判断の記録（ADR）

## 調査前に読む文書

GLOSSARY.md と、調査対象に関連する要件・設計資料・ADR を読む。

文書が存在しない場合は、そのまま作業を進める。
不在を報告したり、事前の作成を提案したりする必要はない。
用語や設計判断が確定した段階で domain-modeling スキルが作成する。

## 用語の使用

Issue のタイトル、提案、仮説、テスト名には、
用語集で定義された用語を使う。

未定義の用語が必要な場合は、プロジェクトで使われている
表現かを再検討する。用語集に不足がある場合は、
domain-modeling で扱う課題として記録する。

## ADR との矛盾

既存の ADR と矛盾する提案は、該当する ADR を明示し、
判断を見直す理由を説明する。
