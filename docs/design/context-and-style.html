責務

Codex app-server は同一threadの継続・再開と、モデルが扱う会話履歴の圧縮を担当する。同一threadの継続・圧縮は接続設計に従う。

scene-craft は原文・要約・制作履歴を保存し、作品の共有情報と依頼に関係する記録を実行へ渡す。

処理 担当と境界
同じ会話の続行 Codexの既存threadを継続・再開する
モデル文脈の圧縮 Codexに任せる
作品共有情報の取得 scene-craftが最新の確定情報を取得し、実行に使った参照を固定する
保存用・他会話参照用の要約 scene-craft側の処理。対象原文の参照を持ち、Codexの内部圧縮とは独立して保存する
根拠の追加取得 許可された作品・対象範囲の要約・原文・履歴を必要に応じて取得し、参照を残す

app-serverのthread/resumeとthread/compact/startは公式OpenAI documentationに記載されている。

共有情報と制作意図

  • 制作意図、現在採用状態、採否と手修正、保護指定、固定した作風は作品単位を正とする。
  • 「夕景もいいかも」は検討中の案。「この作品は夕景に変更して」のような明示的な指示を共有する制作意図の更新根拠にできる。
  • 更新時は指示原文と新しい文章記録を関連付け、訂正前の意図・記入者・時刻も維持する。
  • 制作方針より作品の制作意図を優先する。作品の制作意図を優先して依頼を扱う。
  • 「静かな夜景」の作品で「昼のように明るくして」と頼まれ、両立する調整か意図の変更か判断できない場合は確認する。

実行に渡す文脈

  1. 対象作品、依頼原文、実際の起点となる保存状態、制作意図、保護指定と依頼限定許可、変更範囲、採用済み状態、固定した作風の参照を取得する。未選択・未入力・制作データ未作成の状態を明示する。
  2. 同じ会話の継続はCodexのthreadを利用する。作品の最新情報はscene-craftの確定記録から補う。
  3. 同じ作品の他会話から依頼に関連する要約を選ぶ。必要な原文・採否・手修正・画像等を追加取得できるようにし、参照元を追跡可能にする。
  4. 実行へ渡した文章・保存状態・採否・変更・ファイル・要約と、その要約の対象範囲を記録する。定義と作風はそれぞれのGit参照・使用内容を残す。追加取得も実行に関連付ける。

待機依頼は実行状態設計に従い開始直前に最新の共有情報を確認する。明示した候補の保存状態を起点として維持する。前提が合わなくなれば確認する。

必須情報が揃ったことを確認して実行する。長い履歴は関連範囲を分けて取得し、要約に未反映の原文も参照対象にする。必須情報自体を扱えない場合は原因を示して停止し、必要な対処を求める。利用者が選択したモデルを使う。

要約の更新と原文

  • 依頼の完了・停止・確認待ちを更新の区切りとし、追加された発言を要約する。
  • 要約は対象メッセージID／範囲、作成者・時刻、根拠の参照を持つ。訂正時は新しい文章記録を作り、訂正元を残す。原文を保持する。
  • 次の実行では最新の共有情報、利用可能な要約、要約に未反映の原文を区別する。確定記録にある最新の採否・意図・保護指定を優先する。
  • 要約失敗や中断時も原文・依頼・途中結果を保存する。未要約の範囲と失敗を示す。受信途中・欠落は完全な原文と区別する。
  • 要約処理のLLM呼び出しにも既存の認証・利用上限・停止契約を適用する。要約の具体的な工程契約はエージェント設計へ渡す。

振り返りと根拠

人間が一作品または複数作品を選んで起動する。複数作品の場合は専用会話として対象作品集合を保持する。対象作品の全履歴を分析対象にする。全履歴を対象とすることと、実際に分析で取得・観察できた範囲の説明を区別する。

  • 完成・採用された結果に加え、不採用案と手修正の比較も使う。
  • 実際に参照した作品・保存状態・採否・変更・文章・ファイルを振り返りの参照記録へ固定する。参照対象と分析できた範囲を示す。
  • 結論には具体的な根拠を付ける。記録された事実、人間が明示した理由、AIによる解釈・仮説を区別する。理由未入力を明示する。
  • 残る文章・プレビュー等で分析した範囲と限界を示す。
  • 根拠の文章記録等に更新があれば「根拠に更新あり」と示し、人間が起動した再分析で新しい記録を参照する。

作風の傾向から制作方針へ

振り返り結果には作風の傾向を仮説として示す。人間は項目ごとに採用・編集・保留を選べる。「暖色が多い」という観察を「主役を暖色で際立たせる」という方針へ編集できる。

元の仮説・根拠、人間が編集・採用した内容と判断を追跡可能にする。理由がなければ未入力とする。

採用した変更をGitへコミットし、作品への適用は別に選ぶ。通常制作では選択した版の採用済み制作方針を使い、未確認の作風の傾向は振り返り・方針の検討時に参照する。

新しい作品は作風の版を選ぶか、作風なしで始める。派生開始時も参照元と派生先の選択を区別する。

作品の版更新はGit版管理設計に従い、旧・新参照、選択者・時刻・理由を保持する。定義と作風で異なるコミットを使える。待機中に作風が変わった場合は開始前に旧版継続／新版切替を確認し、自動再実行では版を維持する。

会話履歴の取得

paginated履歴はページングで取得する。保存済み原文を正とし、実行・分析で使った参照の固定と、制作意図・方針の明示更新を維持する。
