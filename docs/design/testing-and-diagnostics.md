# テスト・診断・初期版の受け入れ

[設計Issue](https://github.com/Kurarowa305/scene-craft/issues/14)。2026-11-02、利用者がQ1〜Q7の推奨案を採用し、設計を確定した。CI・実機実行入口の実装、テスト実施、受け入れ完了を意味しない。

## テストの境界

- 停止、再実行、保護、保存等の判定は、LLM・Blenderの代替実装を使って異常系まで自動確認する。
- 本物の接続先との契約確認と、Windows・WSL・Blender・Photoshopを通した実機確認を別途行う。代替実装の成功だけで本物との互換性を判定しない。
- LLM出力は画像の完全一致を合格条件にせず、変更範囲、編集可能性、出力仕様を検査する。表現の良し悪しと採否は人間が判断する。

## 実行の契機

- 自動テストは各PRの作成・更新時にCIで毎回実行する。PR作成時に一度だけ実行する運用にはしない。
- 実機確認は手元のWindows PCから確認コマンドで手動開始し、対象コミット・環境・結果を記録する。自動確認できる処理の後に、Photoshopの表示・再保存等を人間が確認する。初期構築完了時には必ず実施する。
- 自動テストの成功をPRのマージ条件とする。実機確認は各PRの必須条件にはせず、初期構築完了時と必要な変更時に手動実施する。実装時にはCIだけでなく、保護ルールの必須ステータスチェックを設定して確認する。
- 現時点のリポジトリには製品のテストコマンドとCIがない。仕様統合・実装で、実際のテストを実行するCIと手動の実機確認入口を用意する。空の成功ジョブを実装済みのテストとして扱わない。
- 初期構築完了後のローカル検証の選択とPRでの自動CIを区別する。PRの自動CIは今回の指定に従って毎回動かす。実機確認の追加実施は手動で開始する。

## 初期版全体の受け入れ

1. 実作品で10役割を個別に呼び出し、レンダー出力まで進める。
2. 人間がPhotoshopでレタッチし、制作ファイル・プレビュー・作業内容を記録する。
3. 編集案の採否、手修正と理由、保存状態の復元を確認する。
4. 一作品の振り返りと、別作品も使った複数作品の振り返りを確認する。
5. 採用した制作方針をGitコミットから次作品へ明示適用し、参照を確認する。

停止・破損・権限違反等は専用の小さなデータで確認する。必須項目に未検証があれば、初期版全体の受け入れ完了とは扱わない。

## 診断情報

- 依頼・実行・操作のID、状態遷移、エラー、使用版・モデル、処理時間、成果物の検査結果を記録する。
- 認証情報は記録しない。会話原文・画像・制作ファイルは通常ログへ複製せず、参照で結び付ける。
- 通常の診断ログは30日・合計1GiBを上限とし、期限超過または容量超過時に古いものから整理する。制作履歴、失敗理由、受け入れ結果はこの整理の対象から分けて保持する。
- 外部へ渡す診断情報は、本文や個人パスを除外したものを基本にする。除外処理後の内容を人間が確認してから書き出す。資格情報はエラー本文・外部プロセス出力にも含めないよう検査する。
- ログ整理後も、依頼の状態、失敗理由、採否、検査結果と受け入れ証跡を制作記録から確認できるようにする。ログ上限を生成物や制作実体の自動削除へ拡張しない。

## 結果と再確認

各結果に対象コミット、環境（OS・WSL・Blender・Photoshop・Codex等の使用版）、手順、期待結果、実結果、証拠を残し、成功・失敗・未実施を区別する。自動確認と人間の確認は項目ごとに結果を記録し、コマンドが成功しただけで手動項目を成功にしない。実機確認の開始時に対象版と作業データのコピーを用意し、確認後に結果を保存する。

修正後は失敗項目と影響範囲を再確認し、以前の結果も残す。別のコミット・環境の成功を、そのまま現在の結果へ流用しない。必須項目がすべて成功し、実作品の制作導線も確認できた時点で初期版全体を受け入れる。

## 仕様統合・実装への引き継ぎ

設計上の未決事項はない。to-specで本資料と先行設計を統合し、次を利用者が確認できる実装単位へ分割する。

- 一時DB・フォルダー・模擬時計と外部アダプターを使う自動試験、実接続の契約確認、画面と保存状態をまたぐ統合確認。
- PR作成・更新時のCIと必須ステータスチェック。製品のテストコマンドが成立してから有効化し、未実装のテストを成功ジョブで代替しない。
- Windowsから手動起動する確認コマンド、専用シーンと実作品、Photoshopの手動チェックリスト、初期構築完了時の受け入れ記録。
- 診断情報の記録・除外検査・ローテーション・人間の内容確認後の書き出し。

実装時の具体的なコマンド名、CIジョブ名、ログ形式・保存場所は本契約を満たす形で定める。CI・保護ルール・実機入口の実装と全必須確認の実施は後続作業であり、本Issueの設計完了とは区別する。
