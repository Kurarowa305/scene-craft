DESIGN / 01

全体構成とOSの責務

制作の判断を、接続から分ける

Windowsの制作アプリと、WSLの会話・制作管理をつなぐ。ブラウザを閉じても処理は続き、アプリを終了するときに安全に停止する。

主要な契約

項目 決めたこと・受け渡すもの
画面 React・TypeScript・Vite。HTTPで指示し、SSEで進捗を受け取る。
制作・実行管理 Node.js・Fastify。同じ作品の更新順序、保護、停止と再実行を判断する。
Codex接続 WSLのapp-serverをstdioで管理。専用MCPから認可付きUnix socket RPCで制作管理へつなぐ。
Windows補助プロセス 所有するbackground Blenderだけを起動・照合・停止。実行ごとの永続記録を残す。
保存 履歴DBはWSL上のSQLite、制作ファイルはWindows。ルートID＋相対パスを実パスへ変換する。
起動と終了 Windows起動管理プロセスがwsl.exeを保持。二重起動を防ぎ、終了時は安全な停止を待つ。

制約と失敗時の扱い

  • localhostのHost・Originと変更要求を検査する。任意パスや任意シェル文字列を実行しない。
  • ブラウザ切断は実行を維持。WSLとの連絡喪失は新規操作を止め、安全に停止・照合する。
  • バックエンド再起動やMCP再接続だけで制作を再開しない。
