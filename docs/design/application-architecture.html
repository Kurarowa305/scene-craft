実行環境

scene-craft専用stdio MCPを採用する。制作操作のbackground方式と、制作管理・実行管理による検査は維持する。

場所 担当
Windows
  • ブラウザ
  • Blender
  • Photoshop
WSL
  • 会話・制作履歴の管理
  • 依頼の実行管理
  • Codex app-server
  • scene-craft専用ローカルMCPプロセス
Windows 側の制作フォルダ .blend、.psd、テクスチャ、レンダー画像
項目 仕様
起動
  • Windows のショートカットから使うときに起動する。
  • ブラウザを閉じてもローカルの処理を継続し、明示的な「アプリ終了」で停止する。
  • PC 再起動後はアプリを開き、人間が制作の再開を指示する。
処理内容
  • WSL 上で成立した app-server の接続を活かし、Windows の制作アプリから扱うファイルを Windows 側に置く。
  • OS をまたぐファイルアクセス・プロセス管理が必要になる負担を引き受ける。
  • 具体的なドライブと保存ルートは利用開始時に設定し、接続経路は以下の契約に従う。
記録 OS と保存領域を分ける判断の理由・負担は ADR 0005 に記録する。

構成

採用技術

観点 仕様
共通言語 React と TypeScript で会話・作品・編集案の状態を画面へ表現し、Node.js と共通の言語で保守する。
ローカル構成 Fastify に HTTP 受付と静的配信をまとめ、SQLite に一人用のローカル記録を置くことで、別の DB サーバーの運用を避ける。
通信分離 HTTP と SSE は指示と進捗を分け、ブラウザの再接続を依頼の再実行から独立させるために選ぶ。
項目 仕様
画面
  • 画面は React・TypeScript を採用する。
  • ビルドは Vite を採用する。
  • ローカル用途のため初期は静的にビルドした画面を配信する。
バックエンド WSL のバックエンドは Node.js・Fastify を採用し、TypeScript で記述する。
データベース
  • 制作履歴・依頼記録は WSL の Linux ファイルシステム上の SQLite を採用する。
  • データ構造は「作品と制作履歴のデータモデルを決める」、バックアップは「制作データの保存・復元・バックアップ方式を決める」で具体化する。
実行環境の版
  • パッケージの版・DB ドライバーは実装仕様で互換性を確認して固定する。
  • 現在導入済みの Node は 24.21.0、pnpm は 12.11.2。
実装技術
  • React の静的ビルドに Vite、バックエンドの記述に TypeScript を使う。
  • 制作判断・実行管理・外部接続を分け、通信とOSパスをアダプターが扱う。

プロセス

項目 仕様
バックエンド 一つの常駐プロセスに画面配信・制作管理・実行管理を置き 、app-server、専用ローカルMCP、Blender は別プロセスとして扱う。
専用MCP
  • 専用ローカルMCPはCodexがWSL側で起動し、stdioでツール要求と結果を交換する。
  • MCPとバックエンドは認可付きUnix domain socketのローカルRPCで接続し、依頼コンテキスト参照を会話・依頼・実行・世代へ照合する。
  • 契約はエージェント設計に従い、プロセス共有数と具体的な通信スキーマは実装仕様で確定する。
依頼管理
  • バックエンドが依頼を永続管理する。
  • バックエンドが依頼を記録して受け付け、進捗と終端を保存する。
  • 長時間のCPU処理はHTTP受付と独立して実行する。
障害時の利用
  • 一つのバックエンドが終了すると画面配信も使えなくなる。
  • 一方、Codex の認証切れ・利用上限・app-server の障害だけなら、履歴閲覧・手作業の記録・バックアップは継続できるよう責務を分ける。

起動時は実行ファイルの絶対パス等を明示する。

通信とモジュールの責務

観点 仕様
通信方式 ブラウザからの指示は HTTP、進捗配信は SSE を採用する。
受付範囲 画面・指示・進捗を同じ origin から提供し、localhost のみで受け付ける。
再接続 再接続時は保存済み状態を読み、イベントの重複・欠落を照合する。
モジュール 引き受ける責務
画面と HTTP 受付
  • 入力の検証
  • 指示の受付
  • 表示
制作管理 作品・保存状態・編集案・採否・保護指定の判断。制作判断に必要な論理IDと契約を扱う
実行管理 依頼 ID、順序、停止、実行済み操作の照合、再実行予算。ブラウザの生存から独立する
Codex 接続
  • 子プロセスと stdio
  • thread/turn の対応
  • イベント解釈
専用MCPアダプター Codexへ制作ツールを公開し、認可付きの要求と結果をバックエンドへ中継する。依頼の正本・保護・順序・再実行予算は制作管理・実行管理へ照合する
Blender 操作 操作要求・結果・停止の扱い。実行側でも変更範囲と保護指定を確認する
保存
  • 記録・制作ファイルの参照
  • OS パス変換
  • 復元に必要な実体の扱い

制作管理・実行管理が必要とするインターフェースを定義し、Codex・Blender・保存のアダプターを接続する。Host・Origin・変更要求の正当性を照合し、同じoriginの正当な操作を受け付ける。具体的なローカルセッション方式は実装仕様で定義する。

保存領域とパス

項目 仕様
処理内容
  • Windows の制作ルートと WSL の管理データを分ける。
  • 制作ファイルは保存ルート ID と相対パスで参照し、実際の Windows パスと WSL パスへの変換を保存モジュールに集める。
  • ブラウザには作品・生成物の ID を渡し、ローカルファイルの表示・取得はバックエンドを通す。
復元
  • 整合性・復元・バックアップの契約は保存設計へ引き継ぐ。
  • ルートからの逸脱やリンク先も確認する。
認証
  • Codex 用には WSL に scene-craft 専用の保存領域を用意し、普段の開発用 Codex の設定・会話・認証ファイルと分ける。
  • 初回はその領域で同じ ChatGPT アカウントへログインする。
  • Codex 標準のファイル保管を採用し、所有ユーザーにアクセスを限定する。
  • Codex の会話継続用データをどこまで移行対象にするかは、制作記録との区別を保って保存設計で決める。
設定 Codex のプロジェクト設定など別の設定層もあるため、許可するツールと実行設定を接続時に確認する。
項目 仕様
管理領域
  • 管理 DB と Codex 用保存領域は WSL の Linux ファイルシステム上の別ディレクトリとする。
  • Codex は標準の file 保管を使い、ディレクトリを所有者のみアクセス可能にする。
  • 認証ファイルの作成・更新は Codex が行う。
  • scene-craft の制作データ書き出しは含める項目を選ぶ方式とする。
制作ルート
  • Windows の制作ルートは設定で登録し、初期の対象はこの PC のローカルディスクとする。
  • ルート ID と相対パスで参照し、移行時はルートの対応を差し替える。
  • パス変換、リンク先・ルート逸脱の検査は保存モジュールが担う。
  • 具体的なドライブ名は利用開始時に設定する。
記録の照合
  • 記録 DB、Codex の内部状態、Windows の実行記録と生成物を別の役割として扱う。
  • 検証済みファイルと完成記録を照合して作品へ反映する。

起動・終了・再接続

バックエンドがWindows側の実行記録を照合する。アプリ終了時も制作操作の停止・記録を先に確認してから、Codexと専用MCPを含む所有プロセスを終了する。

生存管理

項目 仕様
起動
  • Windowsのショートカットからバックグラウンドの起動管理プロセスを開始する。
  • そのプロセスが wsl.exe を起動して終了まで保持し、WSL 内ではバックエンドを foreground で動かす。
  • 管理プロセスはブラウザから独立し、準備完了後に画面を開く。
起動
  • 管理プロセスの責務は起動・既存インスタンスの確認・終了監視・起動失敗の通知に限定する。
  • 制作の順序や再実行は WSL 側が判断する。
  • 画面を開けない場合も、起動失敗とログの場所を確認できる入口を用意する。
所有権
  • Windows 補助プロセスは実行ごとに所有権を持ち、Blender のプロセスハンドルと実行 ID・PID・起動時刻・実行ファイル・実行用ディレクトリを対応付ける。
  • 実行開始の受付記録を先に残す。
  • 開始直後に落ちて所有権を確定できなかった実行は状態不明とする。
起動
  • 補助プロセスは Windows 側で起動元のシェルから独立して実行し、ログ・要求・処理に必要な入力を Windows 側へ置く。
  • WSL の標準入出力や WSL 内のファイルがなくても、現在の操作を安全な境目まで進めて記録できる構成とする。
処理内容
  • WSL と補助プロセスの交換には実行ごとの Windows 側ディレクトリを使う。
  • 開始・停止要求、進捗、チェックポイント、完成記録を分け、書き込み完了後の記録を読む。
  • 固定の補助プログラムと要求ファイルの参照を起動引数にする。
  • 通知がなくても永続記録を再読できるようにする。
失われたもの 合意した扱い
ブラウザの接続 実行を継続。再接続時に現在状態を取得する
WSL／バックエンドとの連絡
  • Windows 補助プロセスが連絡の期限切れを検出し、新しい操作・工程への進行を止める。
  • 編集中・保存中は安全な境目でチェックポイントを残して止める。
  • レンダーは保存済み入力を持つ専用プロセスを終了する 。
Windows 補助プロセス バックエンドが状態不明として記録。残った Blender の所有権と保存状態を照合し、競合する新しい操作を止める
PC・Windows セッション 次回起動時に記録と実体を照合し、人間の再開指示を待つ

停止状態と記録を照合する。期限、更新方法、停止要求との競合、二重起動の排他方式は実行状態設計で具体化する。保存処理は安全な停止を待ち、強制終了は人間の明示操作で行う。
