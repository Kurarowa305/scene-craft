データモデル

保存状態をつなぎ、判断の理由を残す

作品は完成した一枚を目指す単位。AI案・手修正・採否の分岐をつなぎ、何を見て判断し、どこから次の制作を始めたかを追跡する。

エンティティの所属関係

作品を中心に、会話・依頼・制作の記録を管理する。各エンティティは独自の永続IDを持ち、表示名や保存場所が変わっても同一性を保つ。

主要な契約

エンティティ 保持する情報の要点 責務・契約
作品 作品ID・名前・開始方法・制作意図・作風のGit参照・現在状態 完成した一枚を目指す単位。会話間の共有情報の所属先
会話 会話ID・用途・所属作品／対象作品集合・モデル選択 原文の所属と依頼の入口。Codex thread ID は別の接続対応記録で保持し、会話の ID にしない
原文メッセージ メッセージID・会話・発言者・順序・本文／添付・受信状態 原文を保持する。訂正や要約で置換しない。AI の内部推論を必須の制作記録とはしない
依頼 依頼ID・会話・指示原文・起点・変更範囲・保護と依頼限定許可 一つの目的と停止・再実行予算の単位。自動再実行で新しい依頼 ID にしない
実行 実行ID・依頼・親実行・状態／失敗・入力／出力・実効設定 AI 処理と Windows 側制作操作を識別する。Windows 側操作にも固有の実行 ID を与え、親の AI 実行と関連付ける
再実行の記録 記録ID・依頼・原因・対象実行・累積回数・開始根拠 同一 turn 内の制作操作のやり直しも対応付ける。通常の子処理開始や通信再送と区別する。何を一回として消費するかは実行状態設計で具体化
ファイル参照 ファイルID・作品・役割／形式・由来・相対パス・ハッシュ・可用性 保存済みの特定の実体を識別する。作業中の上書き可能なパスだけを保存状態の根拠にしない
生成物 生成物ID・作品・作成実行・内容・種類・完成判定 AI の成果物。成功・完成と、人間による採用を区別する。通常プログラムによるレンダー・変換も作成した制作実行へ結び付ける
保存状態 保存状態ID・作品・構成ファイル・依存素材・成立／復元可能性・変更記録 ある時点の制作データを固定する。初回を除き親となる状態を変更記録からたどれる
変更記録 変更ID・作品・種別・変更前後・由来・要約／理由。手修正は操作者・作業内容等も保持 制作データの変更前後と由来を一まとまりとして記録する。手修正もこの概念に含め、人間が指定した意味のあるまとまりを単位とし、Blender／Photoshopの操作一つずつは網羅しない。取り込み・派生・復元の特別な参照は下記に従う
編集案 編集案ID・作品・依頼・基準／AI結果の状態・作成実行・変更範囲・代替／依存・修正元 何と何を比較するかを表す。手修正後も AI の結果への参照を維持し、AIによる追加修正は新しい編集案から修正元へつなぐ
採否記録 判断ID・作品・編集案・確認した状態・判断者／時刻・任意の理由・範囲・適用状態 最新の枝先ではなく、実際に見て判断した編集案と保存状態を指す。AI修正・手修正を経た結果も「修正して採用」として記録でき、変更者は各変更記録から判別する。判断前・未選択は明示的な不採用と区別
現在状態の更新記録 更新ID・作品・更新前後の状態・根拠の採否／変更・確定時刻 どの状態を次の制作の出発点にしたかを保持する。案の生成や候補上の手修正だけでは更新しない
文章記録 文章ID・対象・用途・本文・記入者／時刻・訂正元・根拠 変更理由と採用理由を別の対象へ結び付ける。未入力は本文なしとして扱い、後から追加できる
振り返りの参照記録 参照記録ID・依頼／実行・対象作品／状態・採否／変更／文章・分析結果 当時何を根拠に振り返ったかを固定する。後日の理由訂正で過去の分析根拠を書き換えない

保存状態でたどる制作履歴

所属関係とは別に、保存状態を節点、変更記録を枝として制作の経緯をたどる。採否記録は実際に確認した状態を参照する。

制約と失敗時の扱い

  • 確定済みの保存状態を上書きせず、理由・要約の訂正も新しい文章記録として残す。
  • 案の完成・候補上の修正だけで現在状態を更新しない。未選択と不採用は別。
  • 復元は直前と復元元を残す新記録。派生は別作品。理由の訂正や実体削除で過去の判断を消さない。
