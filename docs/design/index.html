SCENE-CRAFT / DESIGN PORTAL

全体像

人間が工程を選び、AIの編集案を確かめ、採用する。scene-craftは制作データと会話、手修正と理由をつないで残す。

01 / SYSTEM

どこで、何を動かすか

制作アプリとファイルはWindows、会話と制作の管理はWSL。専用MCPを通る制作要求も、バックエンドで権限・保護・実行順序を照合する。

全体構成の判断と制約を読む →

02 / CREATIVE CYCLE

人間の判断を挟んで進む

元の制作データを守る

保存済み入力のコピーへ編集し、保護指定と実際の変更を検査する。

採用前の枝も残す

未採用案への手修正・AI修正をつなぎ、確認した状態を採用する。

止まったら照合する

ブラウザ切断と処理中断を分け、外部操作が止まったことを確かめる。

03 / DESIGN AREAS

設計一覧

各設計で作る機能と仕様を確認できます。

全体構成とOSの責務

Windowsの制作アプリと、WSLの会話・制作管理をつなぐ。ブラウザを閉じても処理は続き、アプリを終了するときに安全に停止する。

画面と制作の導線

左に作品と会話、中央にメインチャット、右に横タブ。採否や手作業の記録は会話から行い、成果物・履歴・相談を隣で開く。

データモデル

作品は完成した一枚を目指す単位。AI案・手修正・採否の分岐をつなぎ、何を見て判断し、どこから次の制作を始めたかを追跡する。

LLM接続と費用

Codex app-serverとCodex管理のChatGPTログインを採用する。scene-craftは作品・採否・制作履歴を管理し、契約枠の上限では停止して人間の再開を待つ。

工程別エージェントとツール

人間が工程を選ぶ。同じチャットのthreadを続けながら、今回の役割と権限を受付側で照合する。既定は1案で、比較が必要なときに複数案を提示する。

実行・停止・復旧

同じ作品の更新は順番に行う。停止要求の受付、外部操作が実際に止まったこと、結果の保存をそれぞれ確認する。

編集案の採用と保護

保存済み入力のコピーへ編集案を作り、確認した具体的な状態を人間が採用する。未採用の案に手修正とAI修正を交互に重ねられる。

Blender連携とレンダー出力

WindowsのBlenderをbackground実行し、保存済み入力のコピーをPythonで処理する。Cyclesから16bit RGB・sRGBのPSDを生成し、上限時はPSBへ切り替える。

保存・復元・バックアップ

制作ファイルと依存素材を管理下へコピーし、サイズ・ハッシュ・構成を固定する。WSLのDBとWindowsのファイルは別々に確定し、完成記録を照合する。

参考資料と素材

参考資料は表現や構造の根拠、素材は制作へ取り込むデータ。一般Web・指定フォルダー・Poly Haven・ambientCGを使い、人間の選択と取得実体を結び付ける。

文脈・作風・制作方針

作品の制作意図を最優先に、採用状態・保護・作風を共有する。Codexの文脈圧縮と、scene-craftが残す根拠付き要約を分ける。

Gitの版固定と更新

定義と作風の版はGitを正とする。受付時のコミットを固定し、使ったファイルのblobと実行時の設定・runtimeを追跡する。
