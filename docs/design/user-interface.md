# 専用アプリの画面と制作・記録の導線

[設計 Issue](https://github.com/Kurarowa305/scene-craft/issues/12)。2026-10-24〜25の利用者とのすり合わせをまとめた草案。各ラウンドの合意を反映し、設計全体の最終確認待ちとする。本実装・実機受け入れは未実施。

2026-10-25、利用者の依頼により[操作できるプロトタイプ](prototypes/user-interface/README.md)を作成した。設計確定前に会話と右側タブの導線を評価するためのものとし、試作コードは`prototype/user-interface-12`ブランチに保存する。3領域の役割を保ち、タブの整理方法を3案で比較できる。LLM・Blender・実ファイル操作は定型のデモであり、利用者の評価は未実施。

## 責務と画面構成

画面は作品と操作対象を明示し、会話による制作依頼・採否・手作業の記録と、成果物・履歴の閲覧をつなぐ。採用・保存・停止の成否は、AIの返答だけで確定せず、[編集案](edit-candidates.md)・[保存](artifact-storage.md)・[実行状態](execution-lifecycle.md)の確定記録を表示する。

| 領域 | 内容と役割 |
| --- | --- |
| 左 | 作品ごとにまとめたチャット一覧。作品はChatGPTアプリのプロジェクトをイメージする。各チャット名の右に実行状態のアイコンを表示 |
| 中央 | メインチャット。工程別エージェントへの依頼、制作の説明、採否、記録、確認への回答を行う |
| 右 | 複数のタブを並べる領域。成果物・編集案のプレビュー、サイドチャット、制作履歴、保護一覧、作風・制作方針を開く |

作品名と現在の採用状態は常に分かるようにする。左右の領域幅を調整でき、履歴等を見るときは右側を広げられる。ChatGPTデスクトップアプリを操作の参考とし、実在する特定バージョンの画面・アイコンを検証済みとは扱わない。

別の成果物へのリンクは新しいタブを開き、同じ成果物なら既存のタブを選択する。タブを閉じても成果物・会話・履歴を削除しない。サイドチャットは保存して開き直せる。

## 作品と会話の開始

- 左側の「作品を作成」から、作品名と制作意図を入力する。制作意図は後から会話で補える。空の状態から始めるか、既存の制作ファイルを取り込む。
- 既存の `.blend`・PSD/PSB等は[保存設計](artifact-storage.md)に従って管理下へコピーし、取り込み時点を最初の記録にする。それ以前の制作過程や理由を推測して作らない。
- 新しい作品では作風の版を選ぶか「作風なし」を指定する。派生作品でも派生先の選択として扱い、元作品の版を無条件に適用しない。
- 作品内の「新しいチャット」から工程を選んで会話を始める。工程の自動進行は追加しない。
- 入力欄付近に工程・修正元・モデルを表示して選択できる。未採用の案から修正を始める場合もその保存状態を修正元として示し、採用状態へ差し替えない。
- モデルはアプリの既定値を新規会話へ引き継ぎ、会話ごとに変更できる。既存会話を自動変更せず、変更は次の依頼から適用する。使用不能ならその旨を示し、別モデルへ自動切替しない。

## メインチャットと成果物

制作依頼への返答には編集案・成果物へのリンクを含める。押すと右側にその案のプレビュータブを開く。画像は拡大・移動できる。比較専用の別画面は設けず、案は他の成果物と同じタブ領域で確認する。変更内容・理由・検査結果・案の独立／依存関係等はチャットで説明し、プレビュータブに説明パネルを追加する前提にはしない。

リンクは確認対象となる具体的な編集案・保存状態・ファイルを指す。後から枝先が変わっても、以前のリンクを未確認の新しい結果へ付け替えない。実体が削除・欠落していれば、その状態を示し、別の画像で代替したように見せない。

### 採否と追加修正

- 採用・修正して採用・不採用はメインチャットからのみ指示する。採否ボタンは置かない。対象や範囲が曖昧なら具体化し、明示済みの同じ指示に重ねて確認を強制しない。
- 部分採用は独立して確認・検証できる変更単位を対象にする。依存がある部分は一組で確認する。任意の内部差分を切り出せると約束しない。
- 基準が古い案や複数案を取り込む場合は、現在状態に組み合わせた実際の結果をリンクで提示し、会話で確認してから採用する。元の案・寄与元・保持する手修正を説明する。
- 未採用の案にも手修正を記録し、指定した状態からAIに追加修正を依頼できる。指示した人間と変更したAIを区別し、採用前は作品の現在状態を切り替えない。
- 理由は任意とし、未入力をAIの推測で埋めない。採用の指示、適用中、適用済み、失敗、結果不明を区別する。失敗・不明のときに現在状態が切り替わったと返答しない。

### 手作業の記録

人間がメインチャットで「ここまでを記録して」等と伝え、作業内容・任意の理由を他のメッセージと同様に送る。ファイル・画像を添付でき、そのチャットのセッションで作成した `.blend` 等の成果物もプルダウンから選べる。候補にはファイル名・作成時刻・元の編集案を表示し、どの保存状態かを区別する。

指定した成果物を手修正の起点とすることと、修正後の制作ファイルを登録することを区別する。人間は手修正を保存し、保存済みの作業用ファイルを取り込む。元の確定済み成果物を上書きせず、GUI内の未保存内容を自動取得したとは扱わない。

記録は前回の状態または指定した候補に結び付け、作業内容・変更前後・理由を保持する。理由の後日入力・訂正、変更要約の訂正もメインチャットで対象を指定して行い、以前の文章・記入者・時刻を残す。相談の発言を人間の記録指示として自動確定しない。

LLMが使えない間も、同じ会話欄の「記録として送信」から対象・本文・添付をそのまま登録できる。AIによる整理・要約を完了条件にせず、通常の相談メッセージとは送信時に区別する。

Photoshopでの作業は人間が保存したPSD/PSBとプレビューを登録し、前回の記録・元レンダーとの関係を保持する。Photoshop内部の操作・書き出しを自動化しない。

### `.blend`の記録用プレビュー

1. 指定した保存済み `.blend` の内容と取得条件に対応する既存の画像があれば再利用する。
2. 対応画像がなければWindows Blenderと通常のPythonスクリプトで生成する。LLMなしで利用できる処理とし、元ファイルを上書きせず固定したコピーを使う。
3. 使用するカメラ・フレーム・記録用解像度を表示する。記録用プレビューと正式な13レイヤーのPSD/PSB出力を区別し、正式出力の品質を黙って下げる経路にはしない。
4. カメラ・依存素材等が不足する場合や生成に失敗した場合は原因を示す。本文と制作ファイルの記録は可能とし、プレビューを後から補える。対応しない古い画像を今回の結果として表示しない。

固定入力からの画像生成が可能であることと、製品としての取得処理が検証済みであることは区別する。取得条件・再利用判定・停止・記録との確定順は後続のエージェント契約と実装仕様へ引き継ぐ。

## サイドチャットと手作業の相談

右側のタブでメインの制作と並行して相談する。Blender・Photoshopでやりたいことを伝えて操作方法を質問できるが、操作ガイド専用には限定しない。

- 同じ作品の制作意図・採用状態を共有し、開いた時点のメインの話題と選択中の成果物を引き継ぐ。
- 以後のメインの発言を毎回自動転送せず、必要なメッセージ・成果物を追加で渡せる。古い発言と現在の作品共有情報を区別する。
- 完全に相談専用とし、制作データの変更、手作業の記録、採否、保護変更、制作意図の確定更新、メインへの依頼の受け渡しを行わない。メインチャットと同じ記録用送信機能を付けない。
- 原文・要約と参照した記録を保存し、後から開き直せる。タブを閉じることを実行の停止としない。相談の停止はその入力欄の停止操作で行う。
- メインの制作実行へ別の発言を割り込ませず、相談を別会話として扱う。相談側に制作操作・確定記録用ツールを渡さない具体的な契約は[エージェント契約](https://github.com/Kurarowa305/scene-craft/issues/9)へ引き継ぐ。

## 制作履歴・復元・派生

制作履歴は普段は閉じ、右側の「制作履歴」タブでブランチグラフとして広く開く。節点は保存状態、枝は変更記録、採用の表示は採否記録に対応し、定義・作風を管理するGitコミットとは区別する。

- 編集案の分岐、手修正とAI修正による枝の伸長、採用した状態からの継続を示す。指示者と変更者を区別する。
- ホバーで修正理由・採用理由を確認でき、未入力なら未入力と示す。クリックで対象を固定し、成果物リンクからプレビュータブを開く。
- 選んだ節点をメインチャットに参照として添え、追加修正・手修正の記録・復元・派生を指示する。特定の履歴節点を参照する操作を、現在状態の切替とは扱わない。
- 「ここに戻して」では復元元と戻す直前の状態を説明し、未登録の手修正があれば先に記録する。後続の履歴は残し、復元元を参照する新しい記録を作る。
- 「ここから別作品を作って」では元作品と起点を明示し、独立した派生先を作る。元作品の会話・理由を派生先の発言として複製しない。
- 必要な実体や依存が不足・破損していれば理由を示し、該当する復元・派生を始めない。履歴が残ることと復元できることを区別する。

長いグラフの具体的な配置・折り畳み・描画方式は、上記の関係と理由にたどれる契約を保って画面実装で検証する。比較用の独立画面は追加しない。

## 保護指定

右側の「保護一覧」タブで対象・項目・対応範囲を確認でき、タブ内から保護を削除できる。この削除は継続的な保護解除であり、制作実体の削除とは区別する。保護の追加はメインチャットからも指示できる。

競合時はメインチャットで必要な対象・項目・変更・理由を示し、依頼限定の一時許可と継続的な解除を区別する。一時許可は会話でやり取りし、一覧の削除を代用しない。直接・間接変更、共有材質等の影響は[編集案・保護設計](edit-candidates.md)に従う。

保護違反・検証不能な候補は採用できないことをチャットで説明し、単なる採用指示で検査済みにしない。許可済みでも最新の保護・実際の変更・許可範囲を採用時に照合する。

## 実行状況・停止・再開

左側のチャット名の右に状態アイコンを置く。内部の9状態を一つずつアイコンにせず、以下へ集約する。具体的なアイコンの形はChatGPTアプリを参考に実装時に照合し、未確認の形を確定仕様として記載しない。

| 表示分類 | 対応する内部状態 |
| --- | --- |
| 処理中 | 待機・実行中・停止待ち |
| 確認が必要 | 確認待ち・失敗・状態確認が必要 |
| 停止中 | 保留・中断 |
| 通常 | 実行なし・完了 |

一つのチャットに複数の依頼がある場合は確認が必要な状態を優先する。詳しい状態、現在の処理、待機理由、確認事項、再認証・利用上限・失敗原因、途中成果と再実行回数はチャット内で伝える。完了済みの過去の失敗を永続的に現在の異常として扱うような集約を避け、未解決の対象を識別する。

### 操作対象はチャットで今行っている作業

- 作業中は送信欄の右下に停止ボタンを置く。依頼ごとの停止・再開ボタンを並べず、利用者はそのチャットで今行っている作業を止める。
- 内部では停止対象を該当する依頼・操作へ対応付け、停止要求受付と実際の停止完了を区別する。停止処理中を表示し、新しい操作を始めない。別チャットの作業まで停止しない。
- 再開ボタンは置かず、「続けて」等の明示メッセージで再開する。対象が曖昧な場合は確認し、元の依頼と累積回数を維持する。新しい制作指示による追加修正は別の依頼として扱う。
- 再認証・利用枠回復・ブラウザ再接続・アプリ再起動だけでは再開しない。結果不明なら先に照合し、競合する制作操作を開始しない。
- 依頼全体が失敗・中断しても独立して検証済みの途中成果にはリンクを示し、未完成部分と区別する。全体の完了と案の採用も区別する。
- ブラウザを閉じてもローカル実行が継続する契約を保ち、再表示では保存された進捗・結果を取得する。停止指示や実体の完成を推測しない。

同じ作品内の制作操作・採用・復元等は既存の順序・排他に従う。メインの作業中も固定情報を使うサイドチャットの相談は可能だが、同じ制作データの同時手編集を許可する表示にはしない。

## 作風・制作方針と版選択

右側の「作風・制作方針」タブで使用中の内容・Gitの版・保存状況を参照し、作品に適用する版を選べる。作風の仮説と採用済みの制作方針、未選択と不採用を区別する。制作意図はメインチャットの明示指示で更新でき、過去の作風より優先する。

エージェント定義の版は別項目として設定に置く。定義と作風で異なるコミットを使える。表示名を付けても版の正はGitフルコミットハッシュとし、詳細で確認できる。

- 版変更時は旧・新参照と変更理由を記録する。新しい版ができたことやmainへ統合されたことを、作品への自動適用にしない。
- 待機中の依頼に作風変更が影響すれば、開始前に旧版継続／新版切替をメインチャットで確認する。実行中の切替は安全な停止後の明示操作とする。
- 非互換・欠損・取得失敗は原因と対処を示し、必要な実行だけを止める。閲覧と手作業の記録は続けられる。
- Gitのローカル保持とリモート保存を区別し、「リモート未保存」「リモート保存済み」と確認時刻を表示する。未pushでもローカルの条件が揃えば制作できる。
- 設定から保存先と対象の保持用タグを確認して明示的にGitHubへ保存できる。ローカルコミット・作品への適用・リモート公開は別操作とする。

## 振り返り

作品メニューから一作品、作品一覧で対象を選んで複数作品の振り返りを開始する。専用チャットで対象作品・保存状態・履歴範囲を確認し、[文脈・作風設計](context-and-style.md)の既定範囲と参照固定に従う。複数作品の会話を一作品所属の会話として扱わない。

根拠となる作品・採否・手修正へのリンク、不足、理由未入力、仮説と事実の違いをチャットで返す。根拠の後日訂正があれば更新を示し、過去の分析を上書きしない。

制作方針の項目別採用・編集・保留も専用チャットで指示する。採用した内容のコミット成功を確認し、作品への版適用は別に選ぶ。コミット失敗・作品未適用を適用済みとしない。

## 設定と保存データ管理

LLMなしで全体バックアップ、バックアップからの復元、保存先管理、大容量実体の削除を操作できる。進捗・不足・失敗を設定画面で確認できる。モデル既定値、定義の版、Git保存先と明示公開も設定に置く。

### バックアップ・復元・形式移行

- 全体バックアップでは保存先・必要容量・既知の不足を示す。安全な停止と照合、作業用ファイルの保存を経て書き出し、未登録のGUI内容まで保存したと表示しない。
- 作業中は新しい制作操作・記録更新を止める。停止できない・状態不明なら書き出しを始めない。完了後も停止した作業を自動再開しない。
- バックアップからの復元は空の保存先を選び、既存データへの合流・上書きを初期機能にしない。不足を持つ正常なバックアップと破損したバックアップを区別する。
- Git実体と認証・Codex内部の継続データは含めない。未pushのGitを移行先で復元できる表示にせず、GitHubからの取得・別途認証・明示再開を案内する。
- ローカル保存形式の移行が必要なら対象・変更内容・必要容量・退避先・退避状態を示し、確認後に行う。失敗した移行を成功扱いで開かない。

### 大容量実体の明示削除

設定の「保存データ管理」で対象・容量・影響する保存状態と復元できなくなる内容を示し、人間が明示的に削除する。現在採用中・実行中、別の保存状態・作品で必要な実体は保護する。参照・共有素材の検査と削除は保存設計の契約に従う。

会話・理由・採否・分岐・ファイルの当時の参照は残し、削除済み・欠落・破損・未確認を区別する。削除した状態は履歴から見返せても、実体を使う復元・派生・制作はできないことを示す。タブを閉じる操作や不採用を実体の削除にしない。

## 主要な制作シナリオと操作の入口

以下は設計の確認観点であり、実装テストの結果ではない。

| シナリオ | 入口と期待する流れ |
| --- | --- |
| 作品開始・既存データ取り込み | 左の作品作成 → 空／取り込み、制作意図、作風版／なし → 工程を選んだ新しいチャット |
| 案の確認・部分採用 | メインチャットの成果物リンク → 右のプレビュータブ → メインで具体的な案・状態・範囲を採用指示 |
| 候補のAI修正・手修正の継続 | 候補／履歴の状態参照 → 工程・修正元を明示して依頼、または保存済み手修正を会話から記録 → 確認した状態を採用 |
| 作業方法の相談 | 右のサイドチャットで質問 → 説明を受ける。相談から記録・制作操作・メインへの依頼は発生しない |
| プレビューのない手作業記録 | メインの本文・添付／成果物プルダウン → `.blend`から画像を再利用／生成。生成失敗時も制作ファイルと本文を記録し、後から補完 |
| 理由・要約の訂正 | メインで対象を指定して補記・訂正 → 原文と以前の文章を残して最新を表示 |
| 保護の競合・削除 | メインで対象・項目を確認して依頼限定許可、または保護一覧タブで継続解除。検証不能な案を採用可能にしない |
| 停止・再開・状態不明 | 左のアイコンとメインの説明 → 入力欄右下で現在作業を停止 → 照合後、明示メッセージで再開 |
| 過去状態への復元・派生 | 履歴タブの節点をメインへ参照 → 指示と対象・影響の確認 → 必要な実体と直前状態を保存して実行 |
| 振り返り・制作方針の更新 | 作品メニュー／複数作品選択 → 専用チャットで範囲確認 → 根拠付き分析 → 会話で項目別採否・編集 → コミット → 別途作品へ適用 |
| 版の欠損・リモート未保存 | 作風タブ／設定の版と保存状況 → 同じ参照の復旧または明示選択。影響しない閲覧・記録は継続 |
| 利用上限・認証待ち | 原因・途中成果をチャットで表示 → 履歴閲覧、記録として送信、スクリプトのプレビュー、設定でのバックアップは利用可能 |
| 実体削除・バックアップ・移行 | 設定で対象・容量・影響を確認 → 通常プログラムで処理 → 不足・破損・未完了を区別 |
