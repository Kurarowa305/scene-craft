1. 画面構成

画面は作品と操作対象を明示し、会話による制作依頼・採否・手作業の記録と、成果物・履歴の閲覧をつなぐ。採用・保存・停止の成否は、編集案・保存・実行状態の確定記録を表示する。

領域 内容と役割
左
  • 作品ごとにまとめたチャット一覧。
  • 作品はChatGPTアプリのプロジェクトをイメージする。
  • 各チャット名の右に実行状態のアイコンを表示 。
中央 メインチャット。工程別エージェントへの依頼、制作の説明、採否、記録、確認への回答を行う
右 複数のタブを並べる領域。成果物・編集案のプレビュー 、サイドチャット、制作履歴、保護一覧、作風・制作方針を開く

処理内容

仕様
  • 中央の上部はチャットタイトルだけを表示す。
  • 作品の所属は左の一覧、採用結果はチャットや制作履歴で確認する。
  • 左右の領域幅を調整でき、履歴等を見るときは右側を広げられる。
  • ChatGPTデスクトップアプリを操作の参考とする。
  • 別の成果物へのリンクは新しいタブを開き、同じ成果物なら既存のタブを選択する。
  • サイドチャットは保存して開き直せる。

保護指定

仕様
  • タブ上部の＋から新しいタブを開き、そのタブの内容領域に成果物・サイドチャット・制作履歴・保護一覧・作風と制作方針の種類選択を表示する。
  • 種類の選択後はそのタブに選んだ内容を表示する。

2. 制作の開始

処理内容

仕様
  • 左側の「作品を作成」から、作品名と制作意図を入力する。
  • 制作意図は後から会話で補える。
  • 空の状態から始めるか、既存の制作ファイルを取り込む。
  • 新しい作品では作風の版を選ぶか「作風なし」を指定する。
  • 作風の版のプルダウンでは最新版に「最新」と表示し、過去版と区別する。
  • 派生作品でも派生先の選択として扱う。
  • 各作品名・振り返りプロジェクト名の右に「新しいチャット」の入口を置く。
  • タイトルは最初のリクエスト後にLLMが命名する。
  • LLM利用不可時も会話原文と記録を保存し、仮の会話名を表示する。
  • 入力欄のエージェント選択の先頭に「なし」を置き、新規チャットは「なし」で始める。
  • 実際の送信時に選んだエージェントをその依頼の工程として記録する。
  • 会話ごとに変更できる。
  • 変更は次の依頼から適用する。
  • 使用不能ならその旨を示す。

記録

仕様
既存の .blend・PSD/PSB等は保存設計に従って管理下へコピーし、取り込み時点を最初の記録にする。

モデル

仕様
  • 入力欄付近にエージェント・モデルを表示して選択できる。
  • 入力欄左下の＋から成果物を選び、選択内容を入力欄内に表示する。
  • 未採用案の保存状態を修正元として固定する。

3. メインチャット

依頼

仕様
  • 制作依頼への返答には編集案・成果物へのリンクを含める。
  • 押すと右側にその案のプレビュータブを開く。
  • 画像は拡大・移動できる。
  • 案は他の成果物と同じタブ領域で確認する。
  • 変更内容・理由・検査結果・案の独立／依存関係等はチャットで説明する。

保存状態

仕様
  • リンクは確認対象となる具体的な編集案・保存状態・ファイルを指す。
  • 成果物リンクは作成時に確認した案・保存状態を参照する。
  • 実体の削除・欠落を表示する。

3-1. 編集案の操作

採用判断

仕様
  • 採用・修正して採用・不採用はメインチャットからのみ指示する。
  • 対象や範囲が曖昧なら具体化する。
  • 部分採用は独立して確認・検証できる変更単位を対象にする。
  • 依存がある部分は一組で確認する。
  • 基準が古い案や複数案を取り込む場合は、現在状態に組み合わせた実際の結果をリンクで提示し、会話で確認してから採用する。
  • 元の案・寄与元・保持する手修正を説明する。
  • 未採用の案にも手修正を記録し、指定した状態からAIに追加修正を依頼できる。
  • 指示した人間と変更したAIを区別する。

処理内容

仕様
  • 理由は任意とし、入力された内容を保存する。
  • 採用の指示、適用中、適用済み、失敗、結果不明を区別する。

4. 手作業の記録

記録

仕様
  • 人間がメインチャットで「ここまでを記録して」等と伝え、作業内容・任意の理由を他のメッセージと同様に送る。
  • 入力欄左下の＋で成果物のプルダウンを開き、そのチャットのセッションに対応する .blend 等を選べる。
  • 候補にはファイル名・作成時刻・元の編集案を表示し、どの保存状態かを区別する。
  • 同じプルダウンの最下部からコンピューター上のファイル・画像を添付できる。
  • 記録は前回の状態または指定した候補に結び付け、作業内容・変更前後・理由を保持する。
  • 理由の後日入力・訂正、変更要約の訂正もメインチャットで対象を指定して行い、以前の文章・記入者・時刻を残す。
  • LLMが使えない間も、同じ会話欄の「記録として送信」から対象・本文・添付をそのまま登録できる。
  • 通常の相談メッセージとは送信時に区別する。
Photoshopでの作業は人間が保存したPSD/PSBとプレビューを登録し、前回の記録・元レンダーとの関係を保持する。

処理内容

仕様
  • 指定した成果物を手修正の起点とすることと、修正後の制作ファイルを登録することを区別する。
  • 人間は手修正を保存し、保存済みの作業用ファイルを取り込む。

4-1. .blendの記録用プレビュー

処理内容

仕様
指定した保存済み .blend の内容と取得条件に対応する既存の画像があれば再利用する。
  • 対応画像がなければWindows Blenderと通常のPythonスクリプトで生成する。
  • LLMなしで利用できる処理とする。

記録

仕様
  • 使用するカメラ・フレーム・記録用解像度を表示する。
  • 記録用プレビューと正式な13レイヤーのPSD/PSB出力を区別する。

適用条件

仕様
  • カメラ・依存素材等が不足する場合や生成に失敗した場合は原因を示す。
  • 本文と制作ファイルの記録は可能とし、プレビューを後から補える。

固定入力からの画像生成が可能であることと、製品としての取得処理が検証済みであることは区別する。取得条件・再利用判定・停止・記録との確定順は後続のエージェント契約と実装仕様へ引き継ぐ。

5. サイドチャット

右側のタブでメインの制作と並行して相談する。

採用判断

仕様
同じ作品の制作意図・採用状態を共有し、開いた時点のメインの話題と選択中の成果物を引き継ぐ。

文脈

仕様
開いた時点の文脈共有と、相談専用の権限制限は維持する。

原文

仕様
  • 原文・要約と参照した記録を保存し、後から開き直せる。
  • 相談の停止はその入力欄の停止操作で行う。

参照

仕様
相談用の接続には参照用ツールを公開する。

6. 制作履歴・復元・派生

制作履歴は普段は閉じ、右側の「制作履歴」タブで、左から右へ制作が進むブランチグラフとして広く開く。節点は保存状態、枝は変更記録、採用の表示は採否記録に対応し、定義・作風を管理するGitコミットとは区別する。

採用判断

仕様
  • 編集案の分岐、手修正とAI修正による枝の伸長、採用した状態からの継続を示す。
  • 指示者と変更者を区別する。
  • ホバーで修正理由・採用理由を確認でき、未入力なら未入力と示す。
  • クリックで対象を固定し、成果物リンクからプレビュータブを開く。

復元

仕様
選んだ節点をメインチャットに参照として添え、追加修正・手修正の記録・復元・派生を指示する。
  • 「ここに戻して」では復元元と戻す直前の状態を説明し、未登録の手修正があれば先に記録する。
  • 後続の履歴は残し、復元元を参照する新しい記録を作る。

派生

仕様
「ここから別作品を作って」では元作品と起点を明示し、独立した派生先を作る。

処理内容

仕様
  • 必要な実体や依存が不足・破損していれば理由を示す。
  • 履歴が残ることと復元できることを区別する。

長いグラフの具体的な配置・折り畳み・描画方式は、上記の関係と理由にたどれる契約を保って画面実装で検証する。

7. 保護指定

保護指定

仕様
  • 右側の「保護一覧」タブで対象・項目・対応範囲を確認でき、タブ内から保護を削除できる。
  • この削除は継続的な保護解除であり、制作実体の削除とは区別する。
  • 保護の追加はメインチャットからも指示できる。
  • 保護違反・検証不能な候補は、原因と必要な対処をチャットで説明する。
  • 許可済みでも最新の保護・実際の変更・許可範囲を採用時に照合する。

依頼

仕様
  • 競合時はメインチャットで必要な対象・項目・変更・理由を示し、依頼限定の一時許可と継続的な解除を区別する。
  • 一時許可は会話でやり取りする。
  • 直接・間接変更、共有材質等の影響は編集案・保護設計に従う。

8. 実行状況・停止・再開

左側のチャット名の右に状態アイコンを置く。以下へ集約する。具体的なアイコンの形はChatGPTアプリを参考に実装時に照合する。

表示分類 対応する内部状態
処理中 待機・実行中・停止待ち
確認が必要 確認待ち・失敗・状態確認が必要
停止中 保留・中断
通常 実行なし・完了

表示の優先順位

仕様
一つのチャットに複数の依頼がある場合は確認が必要な状態を優先する。

チャットの詳細表示

仕様
詳しい状態、現在の処理、待機理由、確認事項、再認証・利用上限・失敗原因、途中成果と再実行回数はチャット内で伝える。

未解決の対象

仕様
完了済みの過去の失敗を永続的に現在の異常として扱うような集約を避け、未解決の対象を識別する。

8-1. 操作対象はチャットで今行っている作業

停止

仕様
  • 作業中は送信欄の右下に停止ボタンを置く。
  • 利用者はそのチャットで今行っている作業を止める。
  • 内部では停止対象を該当する依頼・操作へ対応付け、停止要求受付と実際の停止完了を区別する。
  • 停止処理中を表示す。

処理内容

仕様
  • 「続けて」等の明示メッセージで再開する。
  • 対象が曖昧な場合は確認し、元の依頼と累積回数を維持する。
  • 新しい制作指示による追加修正は別の依頼として扱う。
結果不明なら先に照合する。
ブラウザを閉じてもローカル実行が継続する契約を保ち、再表示では保存された進捗・結果を取得する。

依頼

仕様
  • 依頼全体が失敗・中断しても独立して検証済みの途中成果にはリンクを示し、未完成部分と区別する。
  • 全体の完了と案の採用も区別する。

同じ作品内の制作操作・採用・復元等は既存の順序・排他に従う。

9. 作風・制作方針と版選択

Git参照

仕様
  • 右側の「作風・制作方針」タブで使用中の内容・Gitの版・保存状況を参照し、作品に適用する版を選べる。
  • 作風の仮説と採用済みの制作方針、未選択と不採用を区別する。
  • 制作意図はメインチャットの明示指示で更新でき、過去の作風より優先する。
  • Gitのローカル保持とリモート保存を区別し、「リモート未保存」「リモート保存済み」と確認時刻を表示する。
  • 未pushでもローカルの条件が揃えば制作できる。
  • 設定から保存先と対象の保持用タグを確認して明示的にGitHubへ保存できる。
  • ローカルコミット・作品への適用・リモート公開は別操作とする。

設定

仕様
  • エージェント定義の版は別項目として設定に置く。
  • 定義と作風で異なるコミットを使える。
  • 表示名を付けても版の正はGitフルコミットハッシュとし、詳細で確認できる。

参照

仕様
版変更時は旧・新参照と変更理由を記録する。

依頼

仕様
  • 待機中の依頼に作風変更が影響すれば、開始前に旧版継続／新版切替をメインチャットで確認する。
  • 実行中の切替は安全な停止後の明示操作とする。

処理内容

仕様
  • 非互換・欠損・取得失敗は原因と対処を示し、必要な実行だけを止める。
  • 閲覧と手作業の記録は続けられる。

10. 振り返り

処理内容

仕様
  • 左側の「作品を振り返る」から対象選択のモーダルを開き、一作品または複数作品を選ぶ。
  • 採用状態・保存状態に関係なく、各対象作品の全履歴を対象とする。
  • 実際に分析で参照した根拠の固定は文脈・作風設計に従う。
  • 根拠となる作品・採否・手修正へのリンク、不足、理由未入力、仮説と事実の違いをチャットで返す。
  • 根拠の後日訂正があれば更新を示す。

採用判断

仕様
  • 制作方針の項目別採用・編集・保留も専用チャットで指示する。
  • 採用した内容のコミット成功を確認し、作品への版適用は別に選ぶ。

11. 設定

設定の入口

仕様
左側の「設定・保存データ」から設定を開き、バックアップ・保存データ・版とGitの項目を切り替える。

保存データの操作

仕様
LLMなしで全体バックアップ、バックアップからの復元、保存先管理、大容量実体の削除を操作できる。

進捗表示

仕様
進捗・不足・失敗を設定画面で確認できる。

Git設定

仕様
定義の版、Git保存先と明示公開も設定に置く。

11-1. 命名・保存用要約モデル

モデル

仕様
  • エージェント契約の設計で、設定から命名・保存用要約のモデルを変更できるよう指定された。
  • 「命名・保存用要約モデル」を設定項目として設け、初期構築時はGPT-6 Luna（gpt-6-luna）を初期値にする。
  • 制作会話のモデル選択・新規会話への引き継ぎとは別に扱う。

設定

仕様
  • 設定変更は以後の補助処理へ適用する。
  • 指定モデルが利用不可なら原因と設定変更の入口を示す。
  • 未命名・未要約でも会話と制作結果を閲覧でき、LLMなしの記録も継続できる。
  • 具体的な設定画面の配置は実装仕様で定める。

11-2. バックアップ・復元・形式移行

バックアップ

仕様
  • 全体バックアップでは保存先・必要容量・既知の不足を示す。
  • 安全な停止と照合、作業用ファイルの保存を経て書き出す。
不足を持つ正常なバックアップと破損したバックアップを区別する。

記録

仕様
作業中は新しい制作操作・記録更新を止める。

認証

仕様
GitHubからの取得・別途認証・明示再開を案内する。

処理内容

仕様
  • ローカル保存形式の移行が必要なら対象・変更内容・必要容量・退避先・退避状態を示し、確認後に行う。
  • 移行失敗時は退避した構成への復旧を案内する。

11-3. 大容量実体の明示削除

復元

仕様
  • 設定の「保存データ管理」で対象・容量・影響する保存状態と復元できなくなる内容を示し、人間が明示的に削除する。
  • 現在採用中・実行中、別の保存状態・作品で必要な実体は保護する。
  • 参照・共有素材の検査と削除は保存設計の契約に従う。

参照

仕様
  • 会話・理由・採否・分岐・ファイルの当時の参照は残し、削除済み・欠落・破損・未確認を区別する。
  • 履歴と実体の可用性を表示し、必要な実体が揃った状態で復元・派生・制作を受け付ける。

12. 制作シナリオ

作品開始・既存データ取り込み

入口と期待する流れ
  • 左の作品作成 → 空／取り込み
  • 制作意図
  • 作風版／なし → プロジェクト名右の入口で直接新規チャット → 送信時にエージェント選択

案の確認・部分採用

入口と期待する流れ

入口と期待する流れ

作業方法の相談

入口と期待する流れ

プレビューのない手作業記録

入口と期待する流れ

理由・要約の訂正

メインで対象を指定して補記・訂正 → 原文と以前の文章を残して最新を表示

入口と期待する流れ

停止・再開・状態不明

入口と期待する流れ
左のアイコンとメインの説明 → 入力欄右下で現在作業を停止 → 照合後、明示メッセージで再開

過去状態への復元・派生

入口と期待する流れ

振り返り・制作方針の更新

入口と期待する流れ

版の欠損・リモート未保存

入口と期待する流れ
作風タブ／設定の版と保存状況 → 同じ参照の復旧または明示選択

利用上限・認証待ち

入口と期待する流れ
  • 原因・途中成果をチャットで表示 → 履歴閲覧
  • 記録として送信
  • スクリプトのプレビュー
  • 設定でのバックアップは利用可能

実体削除・バックアップ・移行

入口と期待する流れ
設定で対象・容量・影響を確認 → 通常プログラムで処理 → 不足・破損・未完了を区別
