工程別エージェントとツール

10役割、共通の制作契約

人間が工程を選ぶ。同じチャットのthreadを続けながら、今回の役割と権限を受付側で照合する。既定は1案で、比較が必要なときに複数案を提示する。

設計合意済み 本実装・実機受け入れは後続

主要な契約

項目 決めたこと・受け渡すもの
参考調査・シーン計画 出典と検討事項、部品・位置関係・概寸・順序と仮説を提示。採用は人間。
仮形状・定型モデリング 部品ごとに編集できる形状を作り、保存・依存・保護を検査して案を提示。
アセット検索・取り込み 候補と利用条件を提示し、人間が選んだ実体を取得。取り込み結果は編集案で提示。
周辺整備・植物・小物配置 配置範囲・密度・seedと素材を保持。個体の取り出しと二重生成防止を検証。
UV・画像テクスチャ適用 UV・材質ノードと画像依存を残す。向き・縮尺・変更範囲を検査。
空・海・照明・3Dの雲 オブジェクト・ノード・主要設定を残した編集案。見た目は人間が採否を判断。
レンダー出力・引き渡し Cyclesの実パスからPSD/PSBを通常プログラムで生成。13レイヤーと実体の検査で完了。
振り返り・作風の言語化 対象作品の全履歴索引と実参照を固定。根拠付き仮説・項目別の制作方針案を提示。
手作業の操作方法の相談 公式文書を参照して回答。独立した結果記録は作らず、アプリを自動操作しない。

制約と失敗時の扱い

  • 専用stdio MCP → 認可付きローカルRPC → 制作・実行管理。接続資格と依頼コンテキスト参照を、会話・turn・世代へ照合する。
  • 「なし」はメインで相談・採否・記録に対応。サイド相談と補助モデルには更新権限を与えない。
  • 保存・検査・変換はGit固定の通常処理。形状等は共通手順を優先し、足りない場合に生成Pythonを使う。生成コードも保護・停止・予算を通す。
  • 定義は指示・手順のMarkdown＋JSON manifest。固定blob・実runtime・操作IDと結果を残し、生成コードを定義へ自動昇格しない。
  • MCP受付成功は制作完了ではない。長時間処理は操作IDで照合し、切断・停止・結果不明時に二重起動しない。
