主要な契約

項目 決めたこと・受け渡すもの
9状態 待機、実行中、確認待ち、停止待ち、保留、中断、状態確認が必要、完了、失敗。
作品単位の順序 編集・レンダー・採用・復元を直列化。固定状態を読む調査・振り返りは並行可能。開始直前に最新の前提を照合。
確認と再開 安全な停止を確認して実行枠を解放。回答・再開後は待機列の末尾へ戻り、依存・起点・保護を再確認。
最大2回の再実行 初回を含め最大3回。依頼全体・同じturnの修正も共有し、人間の再実行指示でも累積回数を維持。
二重実行の防止 受付キー、操作ID・試行ID、内容ハッシュを保存。同じ内容の再送は照合し、異なる内容は拒否。
世代と所有権 バックエンド世代とWindowsプロセス所有権を照合。5秒ごとの連絡、単調時計で30秒の期限。古い通知で現在の実行を更新しない。
停止と完了の競合 全結果・保存を検証できれば完了とし、停止要求も残す。一部だけなら検証済み成果を残して中断する。

制約と失敗時の扱い

  • このページの流れ図は主経路の要約。9状態の全遷移と異常系一覧は詳細Issueに保持する。
  • 手動停止・認証待ち・利用上限・プロセス終了・結果不明では自動再開しない。状態照合後に人間が再開する。
  • Codex内部の通信再送は予算に数えない。制作操作のやり直しは工程名やモデル変更でも回数をリセットしない。
  • 30秒は死亡判定でも保存中の強制終了期限でもない。停止待ちの間は競合操作を始めない。
  • 個別の依頼を停止する。新しい作品全体停止機能は設けない。独立して検証できた途中成果は人間が利用できる。
