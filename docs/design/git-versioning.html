Gitの版固定と更新

何を使ったかを、コミットで示す

定義と作風の版はGitを正とする。受付時のコミットを固定し、使ったファイルのblobと実行時の設定・runtimeを追跡する。

責務

項目 仕様
処理内容
  • ADR 0001・ADR 0002を前提とする。
  • 定義・作風の版の正はGitフルコミットハッシュ。
  • 作品・実行・保存状態のIDとは区別する。
参照
  • 定義と作風は同じリポジトリに置き、別々のコミットを参照できる。
  • 「作風の傾向」と採用済みの「制作方針」を別の内容として扱い、作品の制作意図を優先する。
処理内容
  • 版管理はコミットの解決・保持・内容の取り出し・互換性確認を担当する。
  • 実行管理は受付・停止・順序・再実行予算、保存はDB・制作ファイルとの整合性とバックアップ全体、エージェント契約は定義の具体的な構造を担当する。
復元 過去の内容を読み出せることと、当時の環境を復元して同じ結果を生成できることは区別する。

ローカル記録の参照契約

記録 保持する情報
Git参照 リポジトリ識別、Gitオブジェクト形式、フルコミットハッシュ、 対応する保持用タグ。ブランチ名・表示名用タグは任意の表示情報
使用内容 定義・作風それぞれのGit参照、使用したエントリ・パスとGit blob識別子。作風未選択を明示
依頼 受付時の使用予定参照、版の選択・切替の記録。同じ受付キーには保存済みの参照を返す
実行
  • 実際に使用した参照
  • 互換性確認結果
  • 実効モデル設定・外部ツール版・実行環境の記録への参照
作品の作風更新 旧参照・新参照、選択者・時刻・理由。以前の実行記録を保持する
保持・リモート保存 保持用タグ、ローカル可用性、保存先のリポジトリ対応、 リモート一致の最終確認時刻・結果。未保存・確認不能・欠損を区別
項目 仕様
復元
  • リポジトリ識別は保存場所・remote URLから独立した永続IDとし、バックアップ・復元で維持する。
  • 復元先のcloneを保存元のリポジトリ識別へ対応付ける。
  • 保存場所の移動後も過去参照を維持する。
Git参照
  • 定義・作風の使用版について、ローカルで作った保持用タグを、そのまま同名・同じ対象コミットのタグとしてGitHubへpushする。
  • 使用内容の識別にはコミットハッシュも残し、保持用タグと両方を記録する。
  • 表示名用タグの併用は任意だが、参照済みコミットの保持用タグは必須とする。
参照
  • 「適用なし」「未選択」「不明」「参照先欠損」を区別する。
  • モデル等の実行時選択は、Gitの既定設定と区別して実効値・変更理由を記録する。

依頼受付・開始・切替

項目 仕様
採用判断
  • 通常制作では利用者が採用した定義の既定コミットと、作品に固定した作風を受付時に解決する。
  • 既定定義の変更は以後の依頼から適用する。
  • 試行は変更ブランチのコミットを明示し、制作データのコピーを使う。
Git参照
  • ローカルの保持用タグと必要なGitオブジェクトの存在を先に確定し、その後、使用予定参照を依頼と一緒にDBへ保存する。
  • 受付失敗は原因を残す。
保護指定
  • 開始直前に制作データ・保護指定・変更範囲を確認する。
  • 受付時に固定した定義・作風を使う。
  • 作品の作風参照が受付時から変わっていれば、旧版で続けるか新版へ切り替えるかを確認する。
  • 回答後にも前提を再確認する。
再実行
  • 自動再実行・通信再送は版を維持する。
  • 人間による切替は動作中の操作と未解決の開始許可がなくなった後に行う。
  • 同じ依頼IDと累積回数を維持し、旧・新参照と理由を残す。
  • 同じ試行IDの通信再送では、保存済みの内容を使う。
  • 未送信を含めて既存の試行がある場合は先に照合し、切替後の実行・試行を別に対応付ける。
停止
  • 失敗・停止した操作をやり直す開始予定記録で、実行状態設計どおり消費する。
  • 版の切替後も累積回数と上限を維持する。
  • 完了済み結果を再利用する場合は、新旧の定義・作風と依存条件の整合性も確認する。

依頼内の明示切替も、作品の作風の現在値を変える操作とは分けて記録する。

Git参照の保持

既存の定義・作風リポジトリに保持用タグを作る。通常のローカルリポジトリとGitHubのremoteを使う。

項目 仕様
処理内容
  • タグは refs/tags/scene-craft/retained/<full-commit-hash> とし、対象コミットを直接指す軽量タグとする。
  • タグ名は保持のための参照であり、ローカル記録の版は引き続きフルコミットハッシュとする。
依頼
  • 作風の作品への選択、依頼受付、版切替などのDB確定前に作る。
  • コミットと使用内容の存在を確認する。
処理内容
  • git update-ref の未作成確認付き操作等で作成する。
  • 既存の同名タグが同じコミットを直接指せば再利用できる。
  • 保持用タグとその参照先を維持する。
処理内容
  • 試行ブランチを削除する前に保持用タグを確認する。
  • 元コミットを保つマージを使う。
処理内容
  • タグ作成をDB確定より先に行う。
  • 起動・保存状態の確認時にはDB参照とローカルのタグ・オブジェクトを照合する。
Git参照 リモート保存は人間が明示的に公開する操作とし、対象の保持用タグをGitHubへ明示的にpushする。
整合性
  • push成功後にリモートの同名タグが記録ハッシュを直接指すことを照合し、保存先と確認時刻を記録する。
  • 同じ対象なら再送は冪等に扱う。
  • 認証・通信失敗や結果不明は未確認として残す。
状況 制作と表示
ローカルのタグ・使用内容が揃い、未push 制作可能。「リモート未保存」と表示
リモートのタグと対象コミットの一致を確認 「リモート保存済み」と最終確認時刻を表示
接続できず現在のリモート状態が不明 最終確認結果と現在確認不能であることを区別。ローカルが揃えば制作可能
ローカルの参照先が欠ける 該当する実行を止める。GitHubから同じコミットを復旧できるか確認
リモートのタグが欠損・異なる対象を指す 不足・不一致を示す
項目 仕様
処理内容
  • ローカルコミットと公開は別操作という既存合意を維持する。
  • pushでは未統合コミットやその祖先の内容も送られるため、公開先の可視性を含めて通常の公開確認に従う。
Git参照
  • GitHubへの保存はPC故障・移行への備えとする。
  • アプリ外からのタグ削除・移動が起きた場合は照合で不足を示す。

固定コミットの利用

項目 仕様
処理内容 使用対象のパス一覧を確定し、コミットのtree／blobから取り出す。
処理内容
  • 定義と作風は別領域へ取り出す。
  • 定義が読み込む指示・手順・同梱ツール等も固定対象に含める。
  • 外部パスへのリンク、欠けたsubmodule・LFS実体等は未解決依存として扱う。
出力
  • 生成スクリプト・ログ・制作出力は別の実行領域へ保存する。
  • 取り出し時に使用パスとblobを照合し、キャッシュを再利用するときも内容の一致を確認する。
  • 保持用タグが指すオブジェクトから再構築する。
処理内容 固定した領域の指示・ツールを読み込み、使用内容を照合する。
処理内容
  • 定義内に同梱するツールはそのblobまで固定する。
  • Node、Codex、Blender、ライブラリ等の外部runtimeは実際の版・設定を記録して互換性を確認する。
整合性
  • その場で生成した操作スクリプトは実体またはハッシュと保持先を記録し、恒久的な定義の改訂とは分ける。
  • Git管理の定義そのものを直す場合は人間の採用・コミットを経る。

定義・作風・現在環境の互換性

定義側の要求、作風側の提供形式、実行基盤側が扱える契約を検査する。契約の識別子は形式・必須項目を判別するためのもので、作風内容の版は引き続きGitコミットで識別する。

状況 扱い
別コミットでも必要な形式・項目が揃う 利用可能
作風未選択で、定義が作風なしに対応する 作風なしと記録して利用可能
作風必須だが未選択、必須項目不足、未対応形式 制作操作前に止め、原因と選べる対処を示す
古い定義が現在のツール契約・runtimeに非対応 互換性のある定義・環境を人間が選ぶ
Git参照先が欠損・破損 欠損を示す

作風を新形式へ直す場合は変更案を人間が採用してコミットし、別途作品への適用を選ぶ。作品の固定参照と過去の実行記録を保持する。人間の採否に属する。

ローカル保存形式の変更

DB・ローカル記録・バックアップ形式のスキーマ識別と、定義・作風のGit版を分ける。

旧アプリへ戻す際は、必要なら旧形式のバックアップも復元する。移行後に追加した制作記録を失い得る復元は、その影響を示して別の明示操作とする。物理的な退避・復元方式は保存設計へ渡す。

制作データのバックアップとGitの復元

制作ファイル・依存素材・会話・制作履歴DBの一括書き出しと復元は引き続き必要とし、通常プログラムで実装する。Gitデータの実体はGitHubへ保存する。保存設計へは次の情報を渡す。

項目 仕様
Git参照 リポジトリ識別、資格情報を含まないGitHubリポジトリの所在、Gitオブジェクト形式。
整合性
  • 作品の固定作風、依頼の使用予定版、全実行、旧・新の切替等が参照するフルコミットハッシュと保持用タグ。
  • 全実行・全判断の参照を対象とする。
処理内容 書き出し時点で確認できたローカル可用性、リモート保存の最終確認結果・時刻、未保存・欠損・確認不能の情報。
項目 仕様
Git参照
  • 未保存分があっても制作データの書き出しは可能とし、Git参照先の不足を明示する。
  • 新しい環境で別途認証する。
復元
  • 復元先では登録したGitHubリポジトリをclone／fetchし、必要な保持用タグを明示的に取得する。
  • 対象タグ、フルコミットハッシュ、使用内容の存在を照合する。
  • 同名タグの参照先が異なる場合は、不一致を示して停止する。
  • 欠損やネットワーク不通ならGit内容は未復旧とする。
  • 復元済みの制作記録の閲覧・手作業の記録は続けられ、欠けた定義・作風を必要とする実行だけを止める。
処理内容
  • ローカル専用のコミットは、元のローカルデータから復旧する。
  • この制約を未保存表示として明示することで、公開を別操作とする運用を保つ。
  • 制作データのバックアップ全体の整合性、部分復元・表示の導線は保存設計で定める。
