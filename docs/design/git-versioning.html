Gitの版固定と更新

何を使ったかを、コミットで示す

定義と作風の版はGitを正とする。受付時のコミットを固定し、使ったファイルのblobと実行時の設定・runtimeを追跡する。

主要な契約

項目 決めたこと・受け渡すもの
参照の固定 リポジトリ・フルコミットハッシュ・保持用タグ・使用パスとblobを記録。定義と作風は別コミットを使える。
受付と待機 受付時の予定版を維持。待機中に作品の作風が変わったら旧版継続／新版切替を確認し、再実行中は黙って変えない。
実行内容の分離 コミット済み内容を読み取り専用領域へ取り出す。未コミットの開発ファイルや暗黙の設定探索を混入させない。
保持と公開 参照済み履歴をrebase・squashで置換しない。タグを移動・自動削除せず、GitHubへ対象タグを明示pushして一致確認。
互換性 定義・作風形式・ツール契約・実runtimeを検査。異なるコミットでも対応可能なら利用し、欠損・非互換なら開始を止める。
ローカル形式の移行 DB等の形式識別を内容の版と分ける。人間の確認、書き込み停止、必要範囲の退避・検証、変換と整合検査を経る。
バックアップからのGit復旧 登録リポジトリから対象タグを取得し、コミット・使用blobを照合。同名タグ不一致をforceで上書きしない。

制約と失敗時の扱い

  • 未pushでもローカルが揃えば制作可能。「リモート未保存」と表示する。接続不能は最終確認結果と区別。
  • Gitコミットだけで外部runtimeの完全復元を保証しない。生成Pythonは恒久的な定義改訂と分ける。
  • 制作データの一括バックアップへGit実体を含めない。復旧・版更新だけで過去の制作を再開しない。
  • 短命なfeature・fix・styleブランチで進め、人間が確認して統合。初期構築完了後の定義・ツール更新に限り検証有無を毎回確認する。
