参考資料と素材

調べる、選ぶ、取り込むを分ける

参考資料は表現や構造の根拠、素材は制作へ取り込むデータ。一般Web・指定フォルダー・Poly Haven・ambientCGを使い、人間の選択と取得実体を結び付ける。

検索対象

参考資料は表現・構造等を検討する根拠、素材は制作データへ取り込んで使うデータとする。同じ画像が両方の役割を持つ場合も、参考として選ぶ判断と制作データへの取り込みを区別する。

対象 初期の扱いと理由
参考調査 一般Web検索で写真・建築資料・作品等を調べる。出典・参考にする要素・制作意図との関係を残す
Poly Haven 外部素材の検索・取得先として採用。HDRI・テクスチャ・3Dモデルを扱い、公式APIとCC0の素材を利用できる
ambientCG 外部素材の検索・取得先として採用。材質等の候補を補い、公式APIとCC0の素材を利用できる
手元の素材ライブラリ 人間が指定したフォルダー内を検索する。選んだ素材と依存素材を管理下へコピーする

外部の自動検索・取得は無料で公開されている素材を対象とする。購入済みの有料素材は手元のライブラリから取り込み、その利用条件を残す。参考資料の保存・素材利用は出典ごとの利用条件を確認する。

候補と実際の取り込みに残す情報

段階 記録する内容
検索

  • 検索語・対象サービスまたは指定フォルダー
  • 検索時刻
  • 結果と取得失敗の区別
候補共通
  • 候補を識別する参照
  • 名前
  • 出典URLまたは元の所在
  • サービスの素材ID（ある場合）
  • 作者
  • プレビューまたは欠けている理由
  • 利用条件・根拠のURLまたは文書参照・確認日
  • 参考にする要素と制作意図との関係
素材候補 提供される形式・解像度・容量、品質やモデルの違い、 既知の依存素材・必要なアドオン等。未取得の詳細は未確認とする
人間の選択
  • 対象候補
  • 参考としての選択／素材取り込みの指示の区別
  • 指示原文・人間・時刻への参照
  • 理由（入力された場合）
取得・取り込み
  • 実際の取得元・時刻・形式・解像度・品質
  • 利用条件の確認根拠
  • 人間の補足
  • 元ファイルと管理下ファイルの対応
  • サイズ・ハッシュ・依存一覧

項目 仕様

  • 取得した実体と依存素材をハッシュで固定する。
記録
  • 検索・参考資料の選択は会話・出典の記録として保存する。
  • 具体的なテーブル分割は実装仕様へ引き継ぐ。

参考画像の保存

項目 仕様
出典 プレビューの出典と、制作へ取り込むファイルの出典・利用条件を区別する。
保存条件
  • 一般Webの参考画像は、保存できる条件を確認できたものを管理下へコピーする。
  • 保存可否が不明なら出典URL・参考要素・制作意図との関係と、画像の可用性を記録する。
記録保持
  • リンク切れや画像の欠落が起きても文章と当時の選択の記録は残す。
  • 当時の参考資料と出典を保持する。
素材への用途変更 役割を変えて取り込む際は素材としての利用条件を確認する。

取得条件

種別 初期の対象と契約
3D
  • .blend、glTF/GLB、FBX、OBJ。
  • 必要な外部ファイル・テクスチャも収集する。
  • モデルの品質違いを明示す 。
画像 PNG/JPEG、EXR/HDR。用途に応じて材質・照明等へ接続し、対象や変更範囲を記録する
取得品質
  • テクスチャは2K、HDRIは4Kを既定とする。
  • 取得前に形式・解像度・容量を提示し、会話で変更できる。
  • 実際に選んだ品質を保存する 。

既定の品質が提供されていない場合も、選べるものを示す。拡張子が対象でも、追加アドオンが必要な素材や読めない内容は保留し、原因を示す。対応形式の設計上の採用と、現在のWindows Blenderでの検証済みを区別する。

素材の取り込み手順

取得後の素材・条件の記録は、その実行が何を使ったかを示す根拠として残す。再取得で内容が異なり、人間が選んだ前提・品質・デザインが変わる場合は確認し直す。

失敗・不足・停止

状況 扱い
検索サービスが利用不可・応答失敗
  • 検索失敗と検索結果なしを区別し、取得済みの候補と出典を残す。
  • 手元の候補は確認できる。
  • 人間が選んだサービス・素材を取得する 。
ダウンロード失敗・容量不足・破損 失敗した取得先・形式・品質と原因、検証済みの途中成果を記録する。取得失敗と原因を返す
利用条件不明 候補の記録は残せるが取り込みは保留。手元の購入済み素材も同様とし、人間が購入時の規約や利用許諾を補足した後に進める
保存できない素材・不足する依存 対象・理由・必要な操作を保存側へ渡す
未対応形式・追加アドオンが必要 原因を示して保留する。原因と対応可能な形式・必要な依存を示して人間の選択を待つ
プレビューだけ取得できない 候補に画像がない理由を示す
停止・アプリ再起動・結果不明 実行状態設計に従い、新規操作の開始を止め、検証済み実体・外部実行・保存記録を照合する

依頼全体の最大2回、同じ試行の通信再送と制作操作のやり直しの区別は実行状態設計を引き継ぐ。検証済みの同一素材を再利用できる場合も同一性を照合する。

サービスの提供条件

APIの利用条件と素材の利用条件は分けて記録する。提供条件は2026-10-31の公式資料を根拠とする。

サービス 公式資料で確認したこと・制限 根拠
Poly Haven
  • APIは商用を含め無料。
  • 素材はCC0。
  • live API利用時はサービス名が分かる出典表示と、ソフト名に対応するRefererまたはUser-Agentが必要 。
API案内、API利用条件、素材ライセンス
ambientCG
  • コードからの検索・取得とv3のassets APIを文書化。
  • 素材ファイルと素材プレビューはCC0。
  • 運営側がAPIの信頼性・安定性の限界を明記 。
 API概要、v3、assets、素材ライセンス

Poly Havenの出典表示は候補に添えるサービス名と出典リンクで満たす構成にする。取得済みの固定実体を保存して再利用する。提供条件が変わり選んだ素材・取得方法を維持できない場合は、原因を示して人間に確認する。

検索と制作操作の境界

観点 仕様
処理の担当 一般Web検索・画像参照・ツール呼び出しと、scene-craftによる出典・利用条件の記録・サービス別取得・管理下コピー・Blender取り込みを区別する。
取得APIの運用 具体的なAPIページング・キャッシュ・アクセス間隔・ファイル選択規則は、採用した条件と利用者の選択を維持する形で定める。
