Blender連携とレンダー出力

編集できる3Dから、13レイヤーへ

WindowsのBlenderをbackground実行し、保存済み入力のコピーをPythonで処理する。Cyclesから16bit RGB・sRGBのPSDを生成し、上限時はPSBへ切り替える。

制作時の使い方

  • 保存した制作データを入力として、元の制作データと分けた編集案を作る。人間は結果を Blender で開いて確認する。
  • 初期構築のレンダー出力は、シーン全体に対する後述の13種類のレイヤーに限定する。形式は16 bit RGBのPSD（上限超過時はPSB）、色空間はsRGBとする。各パスの意味は後述の表に従う。表示用の変換規約は後述の出力契約に従う。
  • 植物などの配置は密度・範囲などをまとめて調整でき、必要な個体を取り出して手修正できる方針とする。取り出した個体は元の分布から除外する。具体的なノード構成は実装仕様で検証する。
  • Material ID と Object ID は、それぞれ材質・物体ごとに異なる色で塗り分けた画像とする。成分出力は Photoshop での色調整・描き足しの使いやすさを優先する。
  • Blender 標準のマルチパス機能で目的を満たせるなら、その機能に合わせる。分離・書き出しは通常プログラムが担当する。標準機能で満たす具体的な出力の組み合わせは、下記の制約を踏まえて確認する。
  • 長いレンダーの停止では現在のレンダーも中断する。レンダー前に保存した制作データと完成済みの出力は残し、中断した画像は人間の再開指示後に作り直す。小さな検証では保存後の所有プロセスを強制終了できた。製品の停止・完成判定の契約は後述する。応答時間と異常系の実機確認は実行状態・受け入れ設計へ引き継ぐ。
  • Diffuse Lighting は影による暗さを含む陰影付きの出力とし、Shadows は影部分の選択・補助調整に使う。ShadowsはCycles標準のShadow Catcherを使い、人間が指定した地面・壁などの受け面を対象とする。

人間とAIは制作データを交互に編集する。編集案の採否と、Photoshopへの読み込み・レイヤー整理・レタッチ・保存は人間が行う。

採用する操作経路と確認範囲

Windows Blender をバックグラウンドで起動し、保存済み入力から Python スクリプトで編集案とレンダーを作る経路を採用する。保存済みの入力をWindows Blenderのbackground処理へ渡す。

Blender 5.2.2 LTSを既存の導入版とし、実行時に使用する版・機能・依存を検査する。実行ファイルの所在は環境設定で解決する。

プロセス終了と成果物の完成は別に判定する。アプリが所有するBlenderプロセスを対象に終了する。

標準レンダー機能の利用

CyclesのRender Passesを使い、Shadowsは指定受け面の標準Shadow Catcherとする。Material color、光・反射、空を除くGlobal Alpha Maskは、以下のレイヤー定義と変換規約に従う。

  • 出力の単位はシーン全体とする。ID の色分けは見えている物体・材質を識別するために使う。
  • 成分の分離には Render Passes を使う。Cycles では Diffuse／Glossy／Transmission の Color・Direct・Indirect、Volume、Emission などがある。使う成分だけを指定する。
  • Cycles の Shadow Catcher は指定した受け側で影を扱うための機能であり、物体の陰影全体を別レイヤーへ移す機能とは区別する。EEVEE の Shadow パスとも仕様が異なる。
  • File Output ノードでパスを個別ファイル、または Multi-Layer OpenEXR として保存できる。初期要件に従い、Photoshop への読み込みとレイヤー整理は人間が行う。
  • 通常のプログラムが指定済みの対象・パス・出力設定から Blender の設定と書き出しを実行する。標準機能で表せない分離要求は未対応または追加設計として示す。

レタッチ用レイヤー

Vue を参考に以下の13種類を希望すると指定された。綴りは Lighting に統一する。Cyclesを基準として実現する。

レイヤー 合意した意味と具体化
統合レイヤー Combined と、必要な合成・表示変換後の画像。どの処理まで含むかを明記する
Material ID 材質ごとに違う色の色分け画像とする。Material Index 等からプログラムで生成する
Object ID 物体ごとに違う色の色分け画像とする。Object Index 等からプログラムで生成する
Material color Diffuse Color を採用。照明を含まない拡散・SSSの色の重み
Specular Lighting 直接の鏡面反射。具体化式は Glossy Direct × Glossy Color。空や発光面の直接鏡面寄与がこちらへ入る場合がある
Diffuse Lighting Diffuse Direct を採用。材質色を含まない直接拡散光。影を含む陰影を残す。Diffuse Directをそのまま使う
Z Depth Depth の距離データと、指定距離範囲を明暗に変換したレタッチ用画像。元の距離情報を中間EXRに区別して保持する
Global Alpha Mask 空を除いた物体のAlphaを採用。3D雲・ボリュームの扱いは下記の出力契約
Shadows 影部分の選択・補助調整用と合意済み。Diffuse Lighting から影を取り除く完全分離は不要。Cycles標準のShadow Catcherを使い、人間が指定した地面・壁などを対象にすると合意済み。影あり／影なしからの近似マスク方式は不採用
Refractions 透過・屈折の直接光と間接光。具体化式は (Transmission Direct + Transmission Indirect) × Transmission Color
Reflections 間接の鏡面反射。具体化式は Glossy Indirect × Glossy Color
Indirect Lighting Diffuse Indirect を採用。材質色を含まない間接拡散光
Ambient Occlusion AO パス。範囲・強度と、統合画像へさらに重ねる用途を定める

出力はシーン全体の13種類に限定する。

パス取得・ID可視化・数式合成・深度変換・書き出しは通常プログラムが担当する。

PSD への引き渡し

利用者は13種類を名前付きの画像レイヤーとして一つの16 bit RGB PSDにまとめる方式を承認した。初期表示は統合レイヤーだけを表示し、残り12種類は非表示とする。方式の採用と実機検証の完了は区別する。

Blender でパスを出力した後、通常のプログラムで PSD を新規生成する。人間が成果物を開いてレタッチする流れとする。PSD 内に出力画像を配置する処理と、Photoshop で人間が行うその後の編集を区別する。

  • 13種類の名前付き画像レイヤーを格納する。初期表示は統合レイヤーだけを表示し、残りは補助素材として非表示にする。
  • 16 bit RGB、sRGBを採用する。sRGBのICCプロファイルを埋め込む。色の画像にはシーンリニアからの変換を行い、ID色・マスク・Z Depthには用途に合う値を符号化する。レイヤーの用途に合う表示変換・数値符号化を適用する。
  • 2026-10-31の実EXR変換検証に基づき、PhotoshopAPI 0.9.1でレイヤーを書き、psd-tools 1.24.0で期待する名称を設定し直し、変換済みCombinedをmerged imageへ直接格納する方式を採用する。psd-toolsの内部APIを使うため版を固定し、更新時は再検証する。一時ファイルを再読込して全レイヤー・merged image・ICCを検証してから完成として公開する。小さなCycles実出力からの13種類の変換とPSD/PSBでの16bit値保持は確認済み。Photoshop実機の表示・編集、大容量の実動作は未確認。
  • PSDの容量・寸法上限を超える場合は同じ13レイヤー・16 bit・sRGBを維持してPSBへ自動切り替えし、出力形式を画面に表示する。指定した解像度とbit depthを維持する。PSB自体の上限や保存容量不足は失敗として示す。
  • 実機確認ではレイヤー数・名称・表示状態、16 bit、色とアルファ、ID 色と深度の保持、Photoshop での開き直しを確認する。ライブラリの合成プレビューの制約も確認する。

根拠: Blender の対応画像形式、PhotoshopAPI、Adobe の大容量文書。

Shadows の採用方式

利用者はCycles標準のShadow Catcherを選択した。Shadowsは指定した地面・壁などの受け面の出力に限定する。影あり／影なしレンダーの比率から近似マスクを作る案は不採用。調査結果は比較の根拠として 調査資料 に残す。

実機確認では、指定した地面からShadow Catcherパスを生成できた。標準仕様に含まれる間接光との相互作用も踏まえ、PSD向け変換は後述の契約に従う。壁・複数受け面・実作品の確認は未完了。

受け面をShadow Catcherにすると同じレンダーのCombinedの見た目も変わるため、通常の統合画像を生成した制作データと、影用の作業コピーを分ける。受け面の指定・追加・削除と未指定時の扱いは、下記の出力契約に従う。

入力・編集可能性の契約

  • 人間はBlenderで手修正を保存してから依頼する。実行時に保存済み .blend と必要な依存素材をコピーし、入力の内容を固定する。画面に「保存済みデータが対象」と示す。元ファイルを保持する。
  • 操作前にBlenderの版、入力・外部素材の存在、カメラ・フレーム・解像度・出力先容量、使用するレンダー機能を検査する。
  • 仮形状は部品単位で選択・編集できるオブジェクトとして残す。UV、画像テクスチャへの接続、材質ノードを残す。空・海・照明・3D雲は、利用したオブジェクト・材質・ノード・主要パラメーターを .blend に残す。利用するアドオン等の依存は一覧に含める。
  • 植物・小物は素材、分布範囲・除外範囲・密度・大きさのばらつき・seedを保存する。選んだ個体を独立して手修正する場合は、元の分布から除外して二重生成を防ぐ。具体的なGeometry Nodes等の構成は実装仕様で検証する。
  • 工程の変更範囲と保護指定を操作要求に含める。編集案は実際の変更を検査し、変更範囲と保護指定に適合した結果を公開する。検査の項目・実現方法は「編集案の採用と保護指定の適用方法を決める」と接続する。

出力の契約

  • 全レイヤーを同じカメラ・フレーム・解像度に揃える。指定した解像度・サンプル数・露出を維持する。13種類は常に名前付きで格納する。寄与ゼロ・取得失敗・未対応を区別して記録する。必須パスの取得結果を検査し、不足時は出力全体を失敗とする。寄与ゼロを確認した成分は正常な空成分として扱う。
  • 対応する数式はシーンリニアの値へ適用する。統合、光、反射、屈折の見た目用画像は、作品に記録した表示変換・露出を用いてsRGBへ変換する。新規作品の表示変換はAgX、露出0を既定値とし、取り込んだ作品の見た目は変更前に確認する。
  • Material colorは材質色としてsRGBへ符号化する。対象ごとに一意のID色を割り当て、作品内の同じ対象に同じ色を使う。ID色・マスク・深度・AOは定義されたデータ値で符号化する。データレイヤーの数値規約をメタデータへ残す。
  • 色との対応に永続的な対象IDを使い、複製・削除再作成・再生成した個体を同一対象とする規則はデータモデル設計へ引き継ぐ。ID色は選択補助とする。Indexパスのアンチエイリアスの制約を受け入れる。
  • Z Depthは近い側が白、遠い側が黒。初回に有限な距離から範囲を提案し、人間が調整できるようにする。採用した近距離・遠距離を保存する。背景・無限遠は黒、範囲外は端へクランプする。元の距離情報は中間EXRに保持する。
  • Global Alpha Maskは背景として扱う空を除いて生成する。World背景を除くだけでなく、空として使うドーム・背景板・雲等は背景対象を明示する。3D雲等が背景か制作物かは作品設定へ残す。Alpha用の作業コピーで背景のカメラ可視性を変える方式を候補とする。レンダーAlpha値を黒0・白1の画像にする。ガラス越し・透過・ボリュームの境界は実機検証対象。
  • Shadowsの受け面は作品の設定として保存し、再レンダーで再利用する。未指定・削除で対象がなくなった場合は実行前に指定を求める。人間が「影の出力対象なし」を明示した場合だけ、変化なしを示す白いShadowsレイヤーを格納し、メタデータに対象なしと記録する。
  • Shadowsは影用の作業コピーで生成した標準Shadow Catcherを利用し、Combinedは通常の制作データから作る。Shadow Catcherの倍率としての値を保持する中間EXRと、sRGB・16bitのレタッチ用画像を区別する。RGB各値を0〜1へクランプし、0を黒・1を白の16bit補助画像として格納する。白を中立値とする0〜1のデータ画像として保存する。1を超える明るい寄与はPSDでは白へ制限されるが、中間EXRには元の値を残す。実装時に見本で確認する。
  • PSD/PSBの13画像はフルキャンバスで位置を揃え、統合のみ表示・通常合成・不透明度100%を初期値にする。補助レイヤーは人間が必要に応じて表示・選択・合成する。半透明を含むカラー画像は書き出し先のalpha規約へ変換し、縁の色を確認する。
  • 中間EXRと実行メタデータはアプリが管理する制作データとして保持する。大きな中間データの削除・保持は保存設計に従う。

メタデータ

出力ごとに作品・依頼・実行・入力の保存状態、入力と出力のハッシュ、Blenderの版、エンジン・デバイス、カメラ・フレーム・解像度・seed・サンプル数、カラーマネジメント設定、ICC識別子、パスの意味と数式・変換方法、ID色の対応、深度範囲、Shadows受け面・背景対象、依存素材、使った定義のGitコミット、完成・欠落・停止・失敗を記録する。モデルが生成した操作スクリプトも、その実行で使った実体またはハッシュと保持先を記録する。具体的な保存構造はデータモデル・保存設計へ引き継ぐ。

Blender操作ModuleのInterface

Blender操作アダプターがPython・Windowsプロセス・OSパス・PSDライブラリを扱う。Windows Blenderを操作するAdapterがその違いを引き受ける。工程の採否・依頼の順序・自動再実行予算は外側の制作管理・実行管理に残す。

操作 受け取るもの 返すもの・契約
読み取り 固定した保存状態の参照 シーン・対象ID・依存素材・設定の要約。固定した入力を読み取る
実行開始 実行ID、固定入力、操作要求、変更範囲・保護指定、出力設定 実行の参照。受付と制作完了を区別する。同じ実行IDの要求には既存の実行結果を返す
状態照合 実行の参照 フェーズ、完了した保存状態・出力、プロセス生存、失敗・不明の情報
停止要求 実行の参照 停止要求の受付。同じ要求には既存の操作の状態を返す。停止完了は別途照合する

固定ツールが入力の検査・コピー・チェックポイント保存・パス設定・PSD生成・検証を担当する。生成スクリプトが必要な制作操作も同じ実行単位の下で行う。新しい制作操作のやり直しは最大2回の予算に含める。

接続と状態

  • WSLからWindows側の補助プロセスを起動し、Windows Blenderをbackgroundで動かす。読み取り／編集／レンダーの入力をファイルで渡し、ログ・進捗・完了記録を取得する。
  • Windows側で実行ID・PID・起動時刻・実行ファイル・実行用ディレクトリを対応付ける。実行ID・PID・起動時刻・実行ファイル・実行用ディレクトリで所有権を照合して終了対象を決める。補助プロセスの具体的な実装とWindows側の生存管理は全体設計・実行状態設計で検証する。
  • 内部フェーズは準備、編集、保存、レンダー、PSD生成、検証に分け、完成したチェックポイントと出力だけを確定する。実行中・停止待ち・成功・失敗・停止・状態不明を区別する。全体の状態機械とDB更新は実行状態設計へ統合する。
  • 読み取りの完了には固定入力の読み取りと要約の検証を、編集の完了には出力 .blend の保存完了と再読み取り確認を、レンダー出力の完了には必要なパスとPSD/PSBの仕様検証を必要とする。終了コードと成果物の検証結果を照合して成功を判定する。非0、必須ファイル欠落、破損・ハッシュ不一致、想定外のレイヤーやbit depthは失敗とする。
  • 書き込み中は完成先と区別した領域へ出力する。ファイル検証後に完成記録を確定し、公開する。再起動時に整合性を照合する。

停止・失敗・再開

  • 人間の停止要求を保存する。編集と保存は安全に止められる境目で止め、完了済みの保存状態を残す。保存処理は安全な境目まで進めて停止する。
  • レンダーは直前の .blend が保存済みの専用プロセスで行う。停止要求時は所有するレンダープロセスを終了して、未完成の画像を不採用とする。OS側の終了を確認して停止済みとする。アプリが所有するプロセスを対象に終了する。
  • 最後の操作を失う強制終了は人間が明示した場合に限定する。
  • 検証済みの途中成果を記録し、13種類が揃ったPSDを完成として渡す。PSD生成だけの失敗なら検証済み中間出力を利用できる。
  • 人間が止めた依頼は、明示的な再開指示を待つ。手動再開時に入力・チェックポイント・完成出力を再照合する。デザインを変える復旧は既存要件どおり人間に確認する。
  • WSLや補助プロセスが落ちた場合、Windows側プロセスの生存と完了記録を照合する。

容量とメモリの判定

PSD/PSBの選択は、寸法・圧縮後サイズ上界・各長さフィールドから事前判定し、実サイズも検証する。失敗を記録して検証済み中間出力を残す。
