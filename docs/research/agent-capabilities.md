# 背景イラスト制作支援エージェントの公開事例調査

調査日: 2026-10-04。これは候補を比較するための調査資料であり、仕様本文ではない。調査後の利用者による候補の選定結果も記録する。

対象は、一人で Blender と Photoshop を使い、静止画の背景イラストを制作する場面。利用者の「海辺の小さなバス停」の制作記録を評価の前提とする。調査した公開例の数から普及率や「最もよく作られる役割」は判断できないため、以下では公開実装・研究で確認できた役割と、アプリの自動化機能を区別する。実機での品質・互換性検証は行っていない。

## scene-craft への示唆（提案）

以下の推奨度は公開例の人気ではなく、利用者が感じた負担、人が残したい判断、操作の定型化しやすさから評価したもの。高は制作基盤に含めることを強く勧める役割、中は具体的な用途を限定すると役立つ役割、低は現状では専用化する理由が弱い役割とする。実装順序や、一工程だけを先に作るという判断は含まない。役割の区分であり、それぞれを独立したプロセスとして実装する判断も含まない。

この表は調査時点の候補である。初期対象の最新の判断は後段の「調査候補に対する利用者の選定結果」を参照する。特に Photoshop 操作は、後の選定で初期対象から外れている。

| 候補となる役割 | 推奨度 | 対象と理由・人に残す判断 |
| --- | --- | --- |
| 参考調査・検討項目の整理 | 高 | 参考画像の候補と決める項目を整理する。素材検索の実装例はあるが、参考資料の解釈は別の仕事。時間帯・配色・雰囲気の採用は人が決める。 |
| シーン計画・制作要素の分解 | 高 | バス停を土台・梁・屋根・ベンチ・標柱へ分解し、必要な部品と位置関係を整理する。配置計画の研究例がある。画面外の構造や地形は仮説として示し、人が意図に合うか判断する。 |
| 定型モデリング・仮形状作成 | 高 | 屋根の波形、梁、柱、ベンチ等の反復作業に合う。形状操作の実装例がある。大まかな配置と主要なシルエットは人が調整できるようにする。 |
| 植物・小物配置と周囲の整備 | 高 | 制作記録で特に負担が大きい。選んだ素材を対象領域・密度・除外領域に従って配置する案。Geometry Nodes による反復配置が根拠。単なるランダム配置で画面が整うとは限らない。 |
| UV・画像テクスチャ適用 | 高 | 人が画像を選び、AI が UV 展開、向き・縮尺、材質への接続を支援する。自動化 API はあるが、見える面での歪み・継ぎ目確認が必要。 |
| アセット検索・取り込み | 高 | 既存素材で作成を省けるものを提示し、採用後の取り込みを支援する。素材の出典・利用条件も候補と一緒に扱う。最終選択は人が行う。 |
| 空・海・照明の基礎設定 | 高 | 指定した時間帯・天気に合わせた初期設定と調整案を作る。物理設定は出発点であり、画面のために人が変更した IOR・粗さ・光を尊重する。3Dの雲生成も含め、レタッチで描くかは作品ごとに人が判断する。手修正を保護する具体的な仕組みは未確定。 |
| 出力・引き渡し支援 | 高 | 画像と編集用データの保存、出力設定の確認を担う。固定処理で足りる部分は通常の自動化として実装でき、毎回 AI 判断を挟む必要はない。 |
| 画面レビュー | 中 | 採用した意図に対して、配置・見え方・不足を指摘する。レンダー画像による反復の研究例がある。修正の採否は人が決め、写実性を唯一の基準にしない。 |
| Photoshop のレタッチ準備・補助 | 中 | レイヤー整理や指定操作の補助から始める候補。筆致や描き込みの表現は人が主導し、雲をレタッチで描くかは作品ごとに決める。API 対応範囲と必要な操作を実機で確かめる。 |
| 構図・カメラの自動決定 | 低 | 技術的な操作例はあるが、利用者が楽しみ、作品の印象を決めたい工程。人の指示による操作や比較案の補助にとどめる案。 |
| 振り返り・作風の言語化 | 高（要求由来） | 完成した作品と制作履歴を参照して、採用・不採用や手修正の理由から作風の傾向を仮説として言語化する。制作方針への採用は人が決める。今回の公開事例から標準的な機能とは断定できず、利用者固有の要求として評価する。 |

## 調査候補に対する利用者の選定結果

2026-10-04〜05 の選定結果は、2026-10-06 に [初期要件](../requirements/initial-scope.md) へ集約した。今後の要件更新はそちらへ反映する。初期の9役割には3Dの雲と振り返りを含み、Photoshop の操作はすべて人間が行う。レイヤー整理を自動化する途中案も採用していない。

## 共通機能として持つことを勧めるもの

制作履歴の記録は、振り返りエージェントを起動したときだけ行うのでは遅い。各工程を個別に使い始める段階から、作品・会話・生成物・編集案・採否・人間の手修正と理由・エージェント改訂履歴の対応を残すことを勧める。これは利用者の要求を満たすための提案であり、公開例に共通する標準仕様という意味ではない。手修正の区切りと理由入力の方針は初期要件に記録した。変更の検出方法は未確定である。

編集案の比較・採用・差し戻しも工程間で共通に扱う候補とする。ファイルの保存や決められた出力手順など、判断の不要な部分は通常の自動処理にできる。エージェントの役割数と、独立した実行プロセスの数を一致させる必要はない。

構図・カメラの自動決定は優先度を低くし、必要なら人が指定した条件で比較案を作る補助として扱う。3Dの雲生成は利用者の選定により対象に含めるが、専用エージェントとして独立させる必要があるかは未確定である。

## 検証すべき境界

- 「定型操作を実行できる」と「今回の画面に適した結果を自律判断できる」を分ける。植物配置、UV、光の調整では、実際の制作データで前後比較が必要。
- 変更範囲と保護指定を基準に編集案を作り、保護指定との競合時は確認する方針が選定済み。保護指定は対象全体と項目単位の両方に対応する。独立した変更ごとの採用、修正して採用する方針、記録した時点へのやり直しも選定済み。対象項目の具体的な操作への対応付け、変更間の依存関係を見分ける方法、復元に必要なファイルの保存方法は実装設計で検討する。
- 会話ログや Blender / Photoshop の操作履歴だけから、手修正の理由や作風を確定できるとは考えない。人間による区切りの指定と任意の短い理由入力で、必要な記録を無理なく残せるか検証する。会話・ファイル・前後の保存状態の作品への紐付けは要件として決定済みであり、具体的な保存形式は実装設計で決める。
- 初期の対象環境は初期要件に記した現在の PC と導入済みの版に決定済み。操作経路、Windows と WSL の役割分担、利用する素材サービスは未選定。公開 API の存在や実行ファイルの存在は、自動操作の動作保証を意味しない。
