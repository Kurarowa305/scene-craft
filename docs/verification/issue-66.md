# Issue #66：シーン計画と仮説の採用 — Windows確認手順

## 実装範囲

工程`planning`（シーン計画）で、採用参考・制作意図を基に本文、部品、位置関係、概寸、制作順序、仮説の根拠と不足を保存する。計画は未採用の提案として保存し、採用・修正・保留はメインチャットの指示原文から独立したツールなしCodexで判定する。判断原文全体（任意理由を含む）、人間、日時と具体的な計画/仮説IDを保持する。計画全体の採用は個別仮説を採用しない。修正案は元計画を残し、新しい未採用計画として保存する。

制作ファイルの変更・Blender・モデリングは本Issueの範囲外。計画保存や採用から自動起動しない。

## 画面操作

1. ショートカットで起動し、上記の定義版を選ぶ。「ChatGPT・モデル」で必要ならログインする。作品を作成（例：作品名「計画66」、制作意図「夕暮れの静かな港。石造りの岸壁と倉庫で奥行きを表現したい」）し、作品名右の「＋」からチャットを開く。
2. エージェント「参考調査」で、例えば「港の岸壁と倉庫の参考を3件調べて保存して」と送る。返答の参考リンクから確認し、実際の候補タイトルを使って「『候補タイトル』を参考として選んで」とメインチャットへ送る。既存作品の採用参考を使ってもよい。
3. 入力欄のエージェントを**「シーン計画」**へ切り替え、次を送る。

   > 採用した参考資料と制作意図からシーン計画を作って保存して。部品、位置関係、概寸と単位、制作順序を示して。参考から不明な構造は仮説とし、根拠と不足も残して。計画と各仮説のIDを教えて。

4. 返答の計画リンクを押す。右側に計画名の詳細タブが開く。本文・部品・位置関係・概寸・順序・仮説の根拠と不足を確認する。計画も仮説も初期は「判断状態：未採用」。下部「参照元」の資料名を押すと、#65の出典付き参考詳細へ到達できる。「固定した根拠・Git版・依頼元」には当時の意図・参考・保存状態・Git参照がある。
5. 実際の計画タイトルまたはIDで、メインチャットへ採用を指示する。エージェント「なし」でも使える。

   > 「実際の計画名」を採用して。構図と制作順序が意図に合うため。

   開いている詳細が「採用」に更新され、人間・日時・原文を確認できる。**仮説は未採用のまま**であることを確認する。
6. 個別仮説について、実際のIDを指定する。

   > 計画ID「実際の計画ID」の仮説「実際の仮説ID」を採用して。

   別の仮説には「仮説『ID』は保留して」と送る。対象の仮説だけ判断が変わる。以前の判断は詳細内に残る。理由は省略でき、AIが推測で補わない。
7. 修正する場合はエージェント「シーン計画」で送る。

   > 計画ID「実際の計画ID」を修正して。岸壁の幅を12mにし、その他を保った新しい計画を保存して。

   元計画に「修正依頼」の原文を残し、新計画は新しいIDと「修正前の計画を開く」を持つ。新計画と仮説は未採用となり、旧案への採用は移らない。
8. 右タブを閉じ、右上「＋」→**「シーン計画」**→計画名から開き直す。ブラウザ再読込後は作品・チャットを再選択して同じ一覧から確認する。アプリ終了→再起動でも、計画・参照元・旧案・判断原文が残る。

## 確認待ち・失敗・停止

- 「あの案を採用して」など対象不明の指示は対象を確認し、保存成功と表示しない。
- 「『計画を採用して』を英訳して」「採用の方法を教えて」から判断を登録しない。
- サイドチャットから採用・保存を依頼しても変更できない。
- 計画応答中にメイン入力欄の停止を押す。停止後のMCPは拒否し、すでに確定した計画・判断を削除しない。未保存の文章を保存済みと扱わない。
- モデリング工程へ自動で進まず、Windows Blenderや制作ファイルが起動・変更されない。
