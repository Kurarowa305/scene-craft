# Issue #63 Windows 実機確認

対象: 会話の自動命名、保存用要約、原文の根拠と訂正履歴。自動試験の代替Codex成功と、実Codex接続・Windowsの人間確認を区別する。利用上限の実消費や認証失効は起こさず、異常系はCIの模擬試験を使う。

## 起動

1. 起動中なら画面の「アプリを終了」で終了する。ブラウザを閉じるだけではバックエンドは終了しない。
2. デスクトップの `scene-craft` を開く。今回ビルドした変更ブランチを、既存の起動設定・データで起動する。
3. Windows側の配置は `%LOCALAPPDATA%\scene-craft\Launcher.ps1` と `Test-Local.ps1`。設定は同ディレクトリの `launcher.json`。更新時に設定は維持する。
4. 「Codexとの会話」で認証済みであることを確認する。必要なら「ChatGPTでログイン」→「専用ログインを開く」→認証後「接続状態を更新」。API従量課金への切替は行わない。

独立したデータで確認する場合はPowerShellから次を実行する。新しい一時WSLデータ領域とWindows確認用ファイルを作成するため、専用データのChatGPTログインが必要になる。既存アプリが同じポートで動いていれば先に終了する。

```powershell
& "$env:LOCALAPPDATA\scene-craft\Test-Local.ps1" -Config "$env:LOCALAPPDATA\scene-craft\launcher.json"
```

確認結果のJSONは `%LOCALAPPDATA%\scene-craft\verification\<run-id>-result.json`。対象コミット、実版、期待結果を記録し、人間確認は `not_run` から手動で更新する。成功・失敗・未実施、実結果、画面の証跡ファイルへの参照を残す。自動項目の成功を人間項目の成功へ転記しない。

## 画面操作と期待結果

| 順 | 操作 | 期待結果 |
| --- | --- | --- |
| 1 | 確認用の新しい作品を作り、「新しいチャット」を開く | 会話名が「未命名」、要約が空 |
| 2 | 「保存用要約・根拠・補助モデル」を開く | 命名・要約モデルの初期値は `gpt-6-luna`（GPT-6 Luna）。制作モデルとは別の設定。既に設定を変更していれば保存済みの値を表示 |
| 3 | モデルが「利用不可」なら実モデル一覧で提供されるモデルを明示選択 | 自動代替しない。変更は今後受け付ける補助処理に適用。未提供のGPT-6 Lunaを実接続確認済みにはしない |
| 4 | 「記録する本文」に `手作業で港の資料を整理した。` と入力し「記録として送信」 | 原文が保存され、未命名のまま。未要約の原文に表示。補助処理は起動しない |
| 5 | 制作側モデルを選び「Codexへのメッセージ」に `夕暮れの港の光について相談したい。まだ採用はしない。` →「Codexへ送信」 | 原文と返答が表示され、別処理で短い会話名が付く。補助処理の完了を待たず制作結果を利用可能 |
| 6 | 完了後「保存用要約・根拠・補助モデル」内を確認 | 保存用要約が追加される。「対象原文と根拠」で記録・依頼・返答のIDと本文をたどれる。「補助処理の履歴」で要求モデル・実モデル・結果状態を確認 |
| 7 | 「会話名を変更」に `港の光の相談（実機確認）` →「会話名を保存」 | 左側の会話名と見出しが更新。処理中に変更できた場合も、後着の自動名で戻らない |
| 8 | `空の色についても相談したい。` をCodexへ送信 | 会話名はそのまま。追加原文を対象に別の要約を追加し、以前の要約を保持 |
| 9 | 要約の「この要約を訂正」→ `未採用の検討内容。人間による補足。` →「要約の訂正を保存」 | 新しい人間の改訂・時刻・訂正元IDが追加。旧要約と根拠原文を保持。LLMを起動しない |
| 10 | ブラウザを再読み込みし、作品と会話を選び直す | 人間の会話名、複数の要約、訂正履歴、原文が同じIDで残る。閲覧から補助処理を自動再送しない |
| 11 | 新しいチャットでCodexへ送信し、応答中に「停止」を押す | 未命名または既に確定した名前を保持。新しい要約を起動せず原文が未要約として残る。補助処理実行中なら「補助処理を停止」でも停止可能 |
| 12 | 停止後に「記録として送信」で本文を保存 | LLMなしで保存可能。未要約を保持。再開は「この依頼を再開」または新しい明示依頼で行う |
| 13 | 通常完了した依頼で補助処理だけ失敗した場合、原因に対処し「未処理の命名・要約を実行」 | 明示操作でのみ再試行。対象原文と当時の失敗履歴を保持 |

制作・採否・保護等の後続機能の完成確認には使わない。要約は保存済み原文を参照する補助文章であり、制作成功や採用の確定根拠にはしない。実際の命名・要約文はモデル出力により変わる。
