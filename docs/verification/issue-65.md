# Issue #65：参考資料を検索して選ぶ — Windows確認手順

## 今回の実装

参考調査工程でCodex組込Web検索を使い、専用MCPの`fetch_reference_page`・`save_reference`で出典、確認日時、本文、参考要素、制作意図との関係を保存する。会話から`select_reference`で選び、人間の原文全体（任意理由を含む）を残す。未選択候補を不採用にしない。画像は保存条件を確認した場合のみWindowsの管理対象ルートへコピーする。制作素材の利用許可は別途未確認とする。

自動試験の外部HTTP・Codexは代替境界であり、実Codexによる検索・サイト側の条件判断・Windows上の保存と画面確認は以下で別途実施する。実機結果は現時点で未実施。

## 起動

既存の設定・認証・保存先を維持して、Windows側のスクリプトを更新する。

```powershell
& '\\wsl.localhost\Ubuntu\home\oyadomaritaiki\scene-craft\scripts\windows\Update-Installation.ps1'
```

起動中なら画面右上の「アプリ終了」を押す。終了後にデスクトップの`scene-craft`をダブルクリックする。最新版のLauncherは新規バックエンドの起動前に、そのチェックアウトを自動ビルドする。起動中の旧プロセスは自動置換しない。ビルド失敗は`BUILD_FAILED`で停止する。設定の既定定義Git版は自動で変更しない。

隔離した実機確認を行う場合は次を使う。既存アプリを終了してポートを空ける。通常の制作フォルダーと別のWindows管理フォルダー・WSL DBを作り、対象コミットと環境、各手動項目の未実施状態をJSONへ残す。

```powershell
& "$env:LOCALAPPDATA\scene-craft\Test-Local.ps1" -Config "$env:LOCALAPPDATA\scene-craft\launcher.json"
```

`%LOCALAPPDATA%\scene-craft\verification`の最新`*-result.json`（実際のファイル名はスクリプト末尾の出力を参照）へ実結果・証跡・成功/失敗を記入する。起動や自動確認が成功しても、手動項目を自動的に成功にはしない。

## 画面操作

1. 左側でテスト用作品を作る。例：作品名「参考調査65」、制作意図「夕暮れの静かな港。石造りの岸壁を描きたい」。作品名右の「＋」でチャットを開く。Git定義が未選択なら「定義・作風」設定で利用できる定義コミットを選ぶ。工程欄に「参考調査」が出る版を使う。定義を変えても既存依頼の固定版は変わらない。
2. 必要に応じて専用ChatGPTログインとモデル選択を行う。送信時の「工程」で「参考調査」を選び、次の例を送る。

   > 石造りの港の岸壁について一般Webで参考資料を2件調べて。出典ページをfetch_reference_pageで取得し、参考要素と制作意図との関係をsave_referenceで保存して。画像保存条件が不明なら画像を保存せずURLだけ残して。各候補のタイトルと参考IDを教えて。

3. 右側の「参考資料」タブを開く。「＋ 新しいタブ」→「タブの種類：参考資料」→「参考資料を開く」でも開ける。出典URL、確認日、作者（不明なら不明）、参考要素、意図との関係、画像未保持の理由を確認する。「取得した本文」を開いて内容を確認する。下部の「検索・ページ取得の記録」には依頼に対応する検索と取得結果が残る。結果一覧未提供を「結果なし」と誤表示していないことを確認する。
4. チャットの「参考資料」にある候補タイトルのリンクから本文・出典・選択履歴のJSONを開ける。保存画像がある候補は右タブの「保存した参考画像」から実体を開ける。
5. 選ぶ候補の**実際のタイトルまたはID**を使い、メインチャットへ送る。例の「港の写真」は実際の候補タイトルに置き換える。

   > 「港の写真」を参考として選んで。岸壁の構造が分かるため。

   「工程なし」でも参考選択は使える。右タブで「参考として選択済み」と指示原文・人間・日時を確認する。他候補は「未選択（不採用ではありません）」のまま残る。理由なしでも選べる。対象が曖昧なときはタイトルまたはIDを明記するよう確認が返る。サイドチャットからは選択・保存できない。

6. ブラウザを再読込し、同じ作品・チャット・右タブを開く。本文、出典、参考要素、画像状態、選択原文が残っていることを確認する。アプリ終了→ショートカットで再起動しても確認する。

## 画像保存・失敗・停止の追加確認

- **保存可**：保存許可が対象画像に適用されるページを指定し、「保存条件の根拠ページと該当の引用を確認して、この画像を参考として管理下に保存して」と依頼する。根拠ページも取得する。右タブに根拠の引用とURL、「管理下に保存済み」、画像リンクが現れることを確認する。PNG/JPEG/WebPに限定。保存先は設定の`fileRoots.managed.path/reference-images/<候補ID>`で、元サイトと元ファイルは変更しない。実機確認用Test-LocalではWindows側の隔離管理フォルダーを使う。
- **条件不明**：許可を確認できない画像ではURLのみ/画像未保持になり、制作素材として利用可能と表示しないことを確認する。無断保存を試す必要はない。
- **リンク切れ**：404となる公開URLを指定してページ取得・候補保存を依頼する。右タブのページ取得記録/候補にリンク切れを示し、既存の選択・本文が消えないことを確認する。別画像への自動置換を認めない。
- **停止**：取得を依頼して応答中にメインの「停止」を押す。以後の取得・候補確定が止まり、既存候補と選択が残ることを確認する。停止前に完了していた保存は残る。ページ取得中の停止は停止履歴を残す。明示再開には既存の再実行上限が適用される。
- **欠落**：専用テストデータだけで保存画像を一時退避して再読込し、「保存画像が欠落・破損しています」と本文・選択が同時に表示されることを確認する。制作中の画像は使わない。
