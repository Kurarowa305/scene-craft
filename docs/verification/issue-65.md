# Issue #65：参考資料を検索して選ぶ — Windows確認手順

## 今回の実装

参考調査工程でCodex組込Web検索を使い、専用MCPの`fetch_reference_page`・`save_reference`で出典、確認日時、本文、参考要素、制作意図との関係を保存する。会話から`select_reference`で選び、人間の原文全体（任意理由を含む）を残す。未選択候補を不採用にしない。画像は保存条件の調査なしでWindowsの管理対象ルートへコピーし、利用条件・根拠・確認日は情報として記録する。不明なら不明と残す。趣味の参考調査の画像をそのまま制作物へ使う素材として扱わない。件数未指定時は20件を目標にし、明示件数を優先する。

自動試験の外部HTTP・Codexは代替境界であり、実Codexによる検索・サイト側の条件判断・Windows上の保存と画面確認は以下で別途実施する。実機結果は現時点で未実施。

## 起動

既存の設定・認証・保存先を維持して、Windows側のスクリプトを更新する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '\\wsl.localhost\Ubuntu\home\oyadomaritaiki\scene-craft\scripts\windows\Update-Installation.ps1'
```

起動中なら左下の「アプリ終了」を押す。終了後にデスクトップの`scene-craft`または`scene-craft UI #102`をダブルクリックする。2026-11-04に両入口を統合済みチェックアウトへ更新した。最新版のLauncherは新規バックエンドの起動前に、そのチェックアウトを自動ビルドする。起動中の旧プロセスは自動置換しない。ビルド失敗は`BUILD_FAILED`で停止する。設定の既定定義Git版は自動で変更しない。

隔離した実機確認を行う場合は次を使う。既存アプリを終了してポートを空ける。通常の制作フォルダーと別のWindows管理フォルダー・WSL DBを作り、対象コミットと環境、各手動項目の未実施状態をJSONへ残す。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\scene-craft\Test-Local.ps1" -Config "$env:LOCALAPPDATA\scene-craft\launcher.json"
```

`%LOCALAPPDATA%\scene-craft\verification`の最新`*-result.json`（実際のファイル名はスクリプト末尾の出力を参照）へ実結果・証跡・成功/失敗を記入する。起動や自動確認が成功しても、手動項目を自動的に成功にはしない。

## 画面操作

1. 左上の「作品を作成」でモーダルを開き、テスト用作品を作る。例：作品名「参考調査65」、制作意図「夕暮れの静かな港。石造りの岸壁を描きたい」。作品名右の「＋」でチャットを開く。Git定義が未選択なら左下「設定・保存データ」→定義の設定で利用できる定義コミットを選ぶ。エージェント欄に「参考調査」が出る版を使う。定義を変えても既存依頼の固定版は変わらない。
2. 必要に応じて左下「設定・保存データ」→「ChatGPT・モデル」から専用ChatGPTログインを行い、設定を閉じる。チャット入力欄の「エージェント」で「参考調査」を選び、会話モデルを選んで、次の例を送る。

   > 石造りの港の岸壁について一般Webで参考画像を調べて。画像と出典、参考要素、制作意図との関係を保存して。利用条件も確認して情報として残して。

3. 返答内に表示される候補タイトルのリンクを押す。右側にその候補名の詳細タブが開く。成果物と共通の大きな画像プレビューが表示され、拡大・縮小・移動・フィットを操作できる。画像の下で出典URL、確認日、作者、参考要素、意図との関係、利用条件と画像保持状態を確認できる。「取得した本文」を開いて内容を確認する。下部の「検索・ページ取得の記録」では結果一覧未提供を「結果なし」と混同していないことを確認する。
4. 一覧から開く場合は右上「＋」（新しいタブ）→「参考資料」を選び、画像グリッドのサムネイルを押す。未指定時の20件の目標と、実際の件数・不足の説明を確認する。候補IDで固定した詳細タブを開き、同じ候補のタブを重複作成しない。保存画像がある候補は詳細内の「保存した参考画像」から実体も開ける。タブの×で閉じても本文や選択は削除されず、チャットのリンクから開き直せる。
5. 選ぶ候補の**実際のタイトルまたはID**を使い、メインチャットへ送る。例の「港の写真」は実際の候補タイトルに置き換える。

   > 「港の写真」を参考として選んで。岸壁の構造が分かるため。

   エージェント「なし」でも参考選択は使える。開いている詳細タブが再読込なしで「参考として選択済み」に変わり、指示原文・人間・日時が反映されることを確認する。他候補の詳細は「未選択（不採用ではありません）」のまま残る。理由なしでも選べる。対象が曖昧なときはタイトルまたはIDを明記するよう確認が返る。サイドチャットからは選択・保存できない。

6. ブラウザを再読込し、同じ作品・チャット・右タブを開く。本文、出典、参考要素、画像状態、選択原文が残っていることを確認する。アプリ終了→ショートカットで再起動しても確認する。

## 画像保存・失敗・停止の追加確認

- **利用条件**：利用条件の記載があるページでは内容・出典・確認日時を情報として保存する。保存許可の調査は依頼しない。記載が確認できない場合は「不明」と表示され、取得できた参考画像は保存される。画像はPNG/JPEG/WebP、保存先は設定の`fileRoots.managed.path/reference-images/<候補ID>`。制作素材としてそのまま使う経路は追加しない。
- **画像グリッドとプレビュー**：一覧では複数列の画像を確認し、クリックで候補名の大きなプレビューを開く。成果物と同じ拡大・縮小・ドラッグ・フィットを操作し、選択原文や利用条件が画像の下に保持されることを確認する。
- **リンク切れ**：404となる公開URLを指定してページ取得・候補保存を依頼する。右タブのページ取得記録/候補にリンク切れを示し、既存の選択・本文が消えないことを確認する。別画像への自動置換を認めない。
- **停止**：取得を依頼して応答中にメイン入力欄の停止ボタン（現在の作業を停止）を押す。以後の取得・候補確定が止まり、既存候補と選択が残ることを確認する。停止前に完了していた保存は残る。ページ取得中の停止は停止履歴を残す。明示再開には既存の再実行上限が適用される。
- **欠落**：専用テストデータだけで保存画像を一時退避して再読込し、「保存画像が欠落・破損しています」と本文・選択が同時に表示されることを確認する。制作中の画像は使わない。

## 自動確認とレビュー

公開HTTP/MCPから一時DB・一時管理フォルダーまで、検索の依頼/turn/item対応、結果未提供/空結果/失敗、候補と選択原文の再起動保持、同じ操作の再送、画像の保存条件根拠・全画素デコード・読出hash検査・欠落・リンク切れ、取得停止、工程権限、非公開URL拒否、相談文から選択しないことを確認する。画像検証は[Sharpの入力制限・破損検査仕様](https://sharp.pixelplumbing.com/api-constructor/)に従い、1600万画素/全フレーム・5秒上限で行う。

ブラウザではチャットの参考リンク、右タブの出典・本文・画像未保持・選択原文、再読込を確認する。既存のサイドチャット等も回帰対象。新規隔離DBの実物をPRAGMAで照合し、27テーブル・101物理カラムと外部キー/UNIQUEを実装一覧へ反映した。Windows PowerShell全4スクリプトの構文を検査し、インストール済みLauncherとリポジトリ版のSHA256一致を確認する。

規約レビューの2件（引数一覧の不一致、候補取得の全作品走査）と仕様レビューの3件（相談文の選択誤認、検索中断の未反映、ヘッダーだけの破損画像の成功扱い）を修正した。対象は着手時`0c3f01d`からの差分。実機受け入れ結果はこの自動確認・レビューと分けて残す。

最終ローカル確認：`npm run check`で型検査・API/保存80件・画面14件・ビルドが成功。追加の検索結果保持の回帰も`tests/references.test.ts`で再確認。画面証跡は`test-results/issue-65-reference-panel.png`。CIは同じcheckをPR作成・更新ごとに実行する。Windowsの実検索・画像条件確認・実機操作は未実施として残す。

## mainのプロトタイプUI統合（2026-11-04）

## 参考画像グリッドと利用条件記録への変更（2026-11-04）

保存条件を調べる手順を廃止し、利用条件を`usageTerms`・任意の根拠ページ/引用・確認日時として保存する。条件不明でも画像取得は行う。参考資料一覧を画像グリッドへ変更し、成果物と同じImagePreviewで大きく表示する。既存の旧permission情報は保持し、新規候補では保存許可の意味に使用しない。件数未指定時の20件はモデルへ既定値として渡し、明示件数を優先、取得実件数と不足を説明する。過去の検証記録にある保存条件確認は変更前の履歴であり、現在の操作は本節に従う。
